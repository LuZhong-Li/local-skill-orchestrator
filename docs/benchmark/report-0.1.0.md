## 1. 环境与口径

| 项 | 值 |
|---|---|
| 本机 | Windows 11 / Node v24.14.1 / runs=3（N=5000 为拐点判定显式用 3 次） |
| SEA 线内核 | 从 `v0.1.0` Release 便携包解包（资产 SHA256 与 `SHA256SUMS.txt` 一致；内核 SHA256 `62fa8785…`；CI 用 Node 22 打包，与本机 Node 24 内嵌运行时不同，故基线以发布内核为准） |
| CI 烟测 | linux/x64、windows/x64、macos/arm64 **双线**各 runs=1，**数值仅记录、不作门禁**（共享 runner 波动 17%~30%）；macOS SEA 线在 EX-13 修复后首次取得真机数据（`scan-cold` 329 ms / 77 MB） |
| 可比性 | 跨线只比总墙钟与峰值内存；跨环境只比量级与拐点；阶段构成只在同线内比较 |

## 2. 阈值判定（N=1000，硬阈值）

| 指标 | 阈值 | 源码线 | SEA 线 | 判定 | 余量 |
|---|---|---|---|---|---|
| `scan` 端到端 | ≤ 30 s | 1.154 s | 1.118 s | **通过** | ≈26× |
| `validate` 端到端 | ≤ 30 s | 1.143 s | 1.082 s | **通过** | ≈26× |
| `export` 端到端 | ≤ 15 s | 0.564 s | 0.504 s | **通过** | ≈27× |
| 峰值 RSS | ≤ 512 MB | **326.4 MB** | 179.9 MB | **通过** | **1.6×（最紧）** |

**结论**：四项全部达标且余量充足。**时间余量 26× 以上，内存余量 1.6× 是唯一需要持续盯的指标**——后续版本若引入全量资产入内存或索引膨胀，内存会最先触到门槛。

阈值取自需求 9.4.3 的 N=1000 收紧值（登记为「**未测先收紧**」：首测接近阈值即登记优化项、不放宽）；实测远离阈值，未触发任何优化项。

## 3. 三档数据（本机 Windows，墙钟中位 / 峰值 RSS）

| 场景 | N=100 源码 / SEA | N=1000 源码 / SEA | N=5000 源码 / SEA |
|---|---|---|---|
| `startup` | 193 / 85 ms | — | — |
| `scan-cold` | 329 / 253 ms | 1154 / 1118 ms | 11370 / 12747 ms |
| `scan-hot` | 381 / 296 ms | 1459 / 1416 ms | 15786 / 17365 ms |
| `validate` | 343 / 256 ms | 1143 / 1082 ms | 8668 / 9557 ms |
| `export` | 276 / 185 ms | 564 / 504 ms | 1712 / 1796 ms |
| 峰值 RSS 上界 | 105.1 / 73.9 MB | **326.4** / 179.9 MB | 626.6 / 540.3 MB |

**索引体积与写入**（阶段归集给出的「序列化 + 原子写」）：索引体积 118 KB（N=100）→ 1.18 MB（N=1000）→ 5.96 MB（N=5000），随规模线性；N=5000 冷扫描的索引写入约 880 ms、热扫描约 912 ms（占墙钟约 8% / 6%），`validate` 无写入动作（其归集值来自栈内匹配，属启发式噪声，按 0 读）。导出体积 N=5000 约 4.97 MB。

## 4. 拐点判定（两轮独立复测，同机同负载口径）

| 场景 | 线 | 单技能 1000 → 5000（第 1 轮 / 第 2 轮） | 判定 |
|---|---|---|---|
| `scan-cold` | 源码 | 1.154 → 2.274 / 2.329 ms（1.971× / 2.018×） | `mild-superlinear` |
| `scan-hot` | 源码 | 1.459 → 3.157 / 3.018 ms（2.164× / 2.069×） | `mild-superlinear` |
| `scan-cold` | SEA | 1.118 → 2.549 / 2.540 ms（2.28× / 2.272×） | `mild-superlinear` |
| `scan-hot` | SEA | 1.416 → 3.473 / 3.387 ms（2.453× / 2.392×） | `mild-superlinear` |
| `validate` | 源码 / SEA | 1.517×~1.802× | `none` |
| `export` | 源码 / SEA | 0.606×~0.766×（**随规模下降**） | `none` |

**判定口径**（裁决原文的三条分支）：两轮都 ≤ 2.0 → `none`；任一轮 > 2.0 且两轮都 ≤ 2.5 → `mild-superlinear`；任一轮 > 2.5 → `significant`。

**结论**：四个 scan 场景落在 1.97×~2.45×，**登记为「轻微超线性观察项」，不优化**（两轮数据稳定、N=5000 无硬阈值门禁、绝对值仅 11~17 s）；怀疑方向是大目录同步遍历与 GC 随规模增长，但当前证据不足以支撑改动。`validate` / `export` 低于阈值，`export` 的单技能成本随规模**下降**（固定成本被摊薄）。**内存无拐点**：每技能平均内存随规模下降（源码线 `scan-hot` 0.326 → 0.126 MB/技能，SEA 线 0.180 → 0.108）。

## 5. 归集覆盖率随档位变化（「规模工作占主导」的证据）

| 场景 | 源码线 100 → 1000 → 5000 | SEA 线 100 → 1000 → 5000 |
|---|---|---|
| `scan-cold` | 0.44 → 0.71 → **0.78** | 0.29 → 0.50 → 0.62 |
| `scan-hot` | 0.50 → 0.74 → 0.71 | 0.21 → 0.41 → 0.53 |
| `validate` | 0.41 → 0.69 → 0.71 | 0.19 → 0.34 → 0.53 |
| `export` | 0.35 → 0.60 → **0.80** | 0.21 → 0.14 → 0.17 |

覆盖率随档位上升，说明 N≥1000 后**六阶段覆盖的成本占比显著提高**、规模工作开始占主导；N=100 时固定成本（进程启动、模块加载）占主导，归集结论在该档位不具代表性。**SEA 线整体低于源码线**（打包后库内部帧名被改写，`parse_yaml` 系统性偏低：同档 N=1000 `scan-cold` 源码 257 ms vs SEA 25 ms）→ 阶段构成只在同线内比较；未归集部分（`other`）以 GC、`(program)` 与本地 fs 帧为主。

## 6. 缺口与待办

| 项 | 状态 | 说明 |
|---|---|---|
| macOS 全矩阵（三档 × 双线 × runs=3） | **部分覆盖** | 无本机 macOS 环境。已覆盖：CI N=100 双线（run 38942732908）、**CI macOS N=1000 双线 + N=5000（SEA 线）**（v0.1.1 批次补，run 38981257916，见 `ci-smoke-0.1.1.json`）、EX-13 的 A/B/C 可执行性验证。**未覆盖并登记**：macOS 源码线 N=5000（该 runner 上异常，按裁决降级为 N=1000 为准）、macOS SEA 启动开销档的峰值（极短进程采样不可靠，该档不参与阈值判定） |
| EX-13（发布缺陷） | **已修复、已验证、已发布** | 根因：SEA 注入缺 `--macho-segment-name NODE_SEA`（Node 官方文档口径）→ macOS 上启动即 SIGSEGV（139）。修复后 **v0.1.1 已发布**；C 组对**新发布物**复核：arm64 与 x64 包内内核 `--version` **exit=0（0.1.1）**、`init → scan` 闭环 **0/0**；`v0.1.0` 的 Release notes 已加已知问题提示（旧版保留） |
| 内核观察项 O-1 | 登记 | 元文件 YAML 错误按 `YAML` 类别落到退出码 3（结果规范 §5.2 第 3 步限定「对象为索引或配置文件」） |
| 内核观察项 O-2 | 登记 | 标识与目录名不一致的技能在索引里出现两条记录（`scanWorkspace` 以目录名删除、以记录 id 为键） |
| 内核观察项 O-3 | 登记 | 环检测问题码在收敛轮被报告清单吞掉（用户只能看到级联结果，看不到根因环） |
| 轻微超线性观察项 | 登记 | 四个 scan 场景 1.97×~2.45×（本文第 4 节），不优化；若后续版本显著恶化（>2.5×）再按设计 §7 定位 |
| 仅观察项 | 登记 | 并发对照（单线程基线 + 预案候选，M3 不含架构改造）；「首跑可能被安全软件扫描放大」需在测量前预热 |
| **退出码口径变化（2026-10-17 内核核查批次）** | **登记，不改基线** | 修复后 `scan` 在本夹具上的退出码由 **3 → 6**（夹具的悬空依赖属 `DEP` 类，按派生规则归 6；此前因技能元文件 YAML 错误被误归 3），`validate` 仍 1、`export` 仍 0。`baseline-0.1.0.json` 是 0.1.0 的真实记录，**原样保留**；本批只涉及问题码/退出码语义，**性能数字未变、无需重录**（修复后小档实测 339 ms vs 329 ms，属波动） |

## 7. 结论

1. **N=1000 四项阈值全部达标**（时间余量 26× 以上、内存余量 1.6×），无需优化批次；**内存是后续唯一需要持续盯的指标**；
2. **拐点判定**：`scan` 两档呈轻微超线性（1.97×~2.45×，两轮复测一致），登记为观察项、不优化；`validate` / `export` 无拐点，内存无拐点；
3. **覆盖率达档位性上升**，规模工作占主导的前提成立；SEA 线阶段归集仅供同线趋势比较；
4. **CI 三平台烟测**可在共享 runner 上重复取得数据，两条 T1 遗留的真机路径（Linux 直读 `/proc`、macOS `ps` 重采样）验证通过；
5. **EX-13 已定位并修复**（构建期产物 A 组可执行），macOS 数据补齐后 M3 方可收官；是否发 `v0.1.1` 补丁由维护者裁决。
