## 1. 项目概述

### 1.1 项目名称

**skill-manager**（Skill 管理器）。

本项目同时是一个可被 AI Agent 加载的独立 Skill，以及一个与其配套的管理工具。二者共享同一份元数据与索引文件。

### 1.2 项目定位

skill-manager 是当前环境下所有已安装 Skill 的**统一元信息管理入口**。

它的职责边界是一句话：

> 只管理 Skill 的**元信息与文件编排**，不执行、不解释、不介入任何被管理 Skill 的业务逻辑。

具体而言，skill-manager 负责：登记已安装 Skill 的元数据、维护清单索引、控制 Skill 的安装、卸载、启用、禁用与更新、检测 Skill 之间的命名与落位冲突、校验元数据与配置、检查依赖、备份与恢复元信息。它不负责：调用 Skill、运行 Skill 内的脚本、解释 Skill 的正文指令、代替 Agent 执行任务。

交付形态有两种，共用同一套内核能力：命令行模式，以及桌面图形外壳。图形外壳只承担视图职责，所有操作都通过调用内核指令完成，不改变内核逻辑，也不实现任何业务判定。

### 1.3 一期任务目标（核心目标）

一期只交付基础能力，目标是把「当前环境里有哪些 Skill、它们从哪来、现在是什么状态」这件事变成可查询、可校验、可控制、可备份的。

一期核心目标如下：

1. **可登记**：能发现当前环境中的已安装 Skill，并把它们的元信息登记到统一索引中。
2. **可查询**：能列出全部已管理 Skill，并查看单个 Skill 的完整元信息与状态。
3. **可控制**：能对单个 Skill 执行安装、卸载、启用、禁用、更新五类操作，并在变更前完成冲突检测。
4. **可校验**：能校验 Skill 的元数据文件是否符合规范，能校验配置文件与索引是否完整一致。
5. **可检查**：能检查 Skill 声明的依赖是否满足，并对不满足项给出可执行的修复提示。
6. **可备份**：能把元信息与索引导出为可迁移的备份文件，并能从备份文件恢复。

一期**不追求**的功能完备度：不追求在线生态接入、不追求跨设备协同、不追求多 Agent 的自动分发同步、不追求自动更新与后台升级。

### 1.4 阶段说明

本项目分期推进。一期只实现基础能力；所有扩展功能留到后续迭代，不在本文档中定义细节。

| 阶段 | 范围 |
|---|---|
| 一期（本文档） | 元数据登记、清单索引、生命周期管理（安装 / 卸载 / 启用 / 禁用 / 更新）、YAML 校验、依赖检查、冲突检测、备份导出与导入；命令行模式与桌面图形外壳 |
| 二期及以后 | 在线检索与市场接入、分组与预设、多 Agent 自动分发与同步、多设备协同与合并、自动更新与后台升级、对外 API 接口层、审计与统计能力、包固化与可复现锁定等 |

阶段划分的原则：一期只做「管理元信息所必需的最小闭环」，任何可以被推迟而不影响闭环完整性的能力，一律推迟。

## 2. 用户需求

### 2.1 目标用户与使用场景

目标用户分为两类：

| 用户类型 | 特征 | 典型使用场景 |
|---|---|---|
| 人类用户（开发者 / 使用者） | 在本机或项目中安装了多个 Skill，需要了解与控制自己的 Skill 资产 | 想知道装了什么、从哪来、要不要更新、怎么临时关掉一个 Skill、怎么把配置搬到另一台机器 |
| AI Agent | 需要在任务中查询或调整 Skill 状态，但不应该直接修改 Agent 目录 | 通过 skill-manager 提供的指令查询与操作，避免绕过管理器导致元信息失真 |

### 2.2 用户想达成的目标

用户使用 skill-manager，是为了达成以下目标：

1. **看清家底**：在一个地方看到当前环境里所有已安装 Skill，而不是逐层翻找各个隐藏目录。
2. **知道来源**：知道每个 Skill 来自哪里（本地自建、Git 仓库、归档包），以及版本与提交标识。
3. **掌握状态**：知道每个 Skill 当前是启用还是禁用，以及它被部署到了哪些目标位置。
4. **临时关停而不删除**：暂时让某个 Skill 不生效，同时保留文件和元信息，之后可以原样恢复。
5. **安全地装卸**：安装与卸载过程可预演、可回滚，不破坏既有文件，不丢失本地改动。
6. **信任元数据**：确认 Skill 的元数据符合通用规范，避免装进来一个不合规、缺字段、无法被 Agent 正确识别的 Skill。
7. **提前发现断链**：在真正使用前就知道某个 Skill 依赖的其他 Skill 或运行环境是否缺失。
8. **可迁移可恢复**：把 Skill 资产与状态备份下来，换机器或重装后可以恢复。

### 3.2 FR-01 元数据登记与发现

**需求描述**

skill-manager 必须能够发现当前环境中已安装的 Skill，并将其元信息登记到统一索引中。用户可显式指定一个或多个 Skill 根目录；未指定时使用配置中的默认根目录集合。

对于无法判定来源的 Skill，必须登记为「来源未知」状态，而不是拒绝登记或抛出错误。

**输入**：Skill 根目录（一个或多个，可来自配置或参数）。

**处理要求**

1. 遍历根目录下的一级子目录，识别其中包含技能元数据文件（`SKILL.md`）的目录为 Skill；
2. 读取元数据文件中的必需字段与可选字段；
3. 对已在索引中的 Skill 更新其元信息；对索引中存在但磁盘上已消失的 Skill，同样以运行期结论为「校验不通过」写入，并给出对应问题码；
4. **对元数据不合格的 Skill 同样写入索引**，以运行期结论为「校验不通过」承载其问题码；不得静默丢弃，也不得因单条不合格而中断整次扫描；
5. 同一 Skill 重复扫描时**更新既有记录，不新增重复条目**；问题修复后再次扫描，其结论自动转为「校验通过」，无需人工干预；
6. 对运行期结论为「校验不通过」的记录，**拒绝其启用操作**，但保留查看与卸载能力，以便用户处理问题；
7. 登记结果写入全局索引文件。

**输出**：更新后的全局索引；一份登记结果摘要（新增 / 更新 / 失效 / 来源未知的数量）。

**验收标准**

1. 扫描完成后，索引中**可用记录**（运行期结论为「校验通过」）的数量恰好为 N 条；
2. 不合格 Skill 以运行期结论为「校验不通过」入索引并携带问题码，不得静默丢弃；该类记录在列表、详情与校验报告中均可见；
3. 重复执行登记不产生重复记录（幂等）；
4. 来源未知的 Skill 被标记为「来源未知」而非报错中断；
5. 修复不合格项后再次扫描，该记录自动转为「校验通过」，无需人工干预。

### 3.3 FR-02 清单索引生成与刷新

**需求描述**

skill-manager 必须维护一份全局索引文件，作为「当前环境 Skill 家庭状况」的唯一事实源。索引必须可由元数据重新生成，且生成过程不修改任何 Skill 自身文件。

**输出**：全局索引文件。

**验收标准**

1. 索引文件包含项目版本标识与生成时间，便于判断新旧；
2. 索引中的每条记录可定位到对应 Skill 的实际目录；
3. 删除索引后重新执行刷新，可从元数据完整重建（索引是可重建的派生物，而非不可再生资产）；
4. 刷新过程中不写入、不修改任何被管理 Skill 的文件。

### 3.4 FR-03 清单索引查询

**需求描述**

用户必须能够列出全部已管理 Skill，并查看单个 Skill 的完整元信息与状态。

**列表视图至少包含**：Skill 标识、名称、版本、状态（启用 / 禁用）、来源类型、部署目标、最近更新时间。

**详情视图至少包含**：完整元数据字段、来源信息（类型、地址、引用标识、子路径）、内容指纹、依赖声明、各部署目标的位置与启用状态。

**验收标准**

1. 列表与详情输出均可切换为机器可读结构，供 Agent 与脚本消费；
2. 支持按状态、来源类型、目标位置过滤；
3. 当索引不存在时，给出明确的引导提示，而不是报错崩溃。

### 3.5 FR-04 Skill 安装

**需求描述**

用户必须能够把一个 Skill 从受支持的来源安装到环境中，安装完成后该 Skill 被自动登记进索引。

**一期受支持的来源类型**：本地目录、Git 仓库地址（可指定分支、标签或提交）、本地归档文件。

**关键要求**

1. **内容落位**：Skill 文件先被放置到中心库位置，再由中心库分发到目标位置；中心库是原件，目标位置是副本。安装的默认行为**包含分发**，即安装完成后该 Skill 已在目标位置就位；
2. **默认启用**：安装完成后，该 Skill 的启用状态置为已启用。启用与禁用用于在安装之后切换可见性，不重复分发内容；
3. **仅落库方式**：安装必须支持仅落库方式，即只写入中心库并完成登记、不向任何目标位置分发。此时该 Skill 的启用状态置为已禁用，可由后续的启用指令补齐落位；
4. **来源登记**：安装时必须记录来源信息，字段的必填性按下列规则判定，必填字段缺失时不得静默通过：
   - 来源类型为必填；
   - 当来源类型不是本地目录、也不是来源未知时，来源地址与引用标识同样必填；
   - 子路径为可选。
5. **预演**：安装必须支持预演模式，展示将要写入的位置与文件，不产生实际变更。
6. **原子性**：安装过程中若任一步骤失败，环境必须回到安装前的状态，不得留下半安装的残留。
7. **冲突处理**：目标位置已存在同名 Skill 时，必须给出明确提示并提供选择，不得静默覆盖。
8. **重复安装保护**：同一来源重复安装必须被识别，并给出「已安装」提示或引导至更新操作。
9. **与启用、禁用的分工**：安装负责把内容放入中心库并分发到目标位置；启用与禁用负责在安装之后切换该 Skill 在各目标位置的可见性，不承担内容分发职责。

**验收标准**

1. 安装成功后，索引中出现该 Skill 且来源字段完整；
2. 安装成功后，该 Skill 在目标位置就位，且启用状态为已启用；
3. 使用仅落库方式安装后，目标位置不存在该 Skill 的文件，且启用状态为已禁用；
4. 预演模式执行后，文件系统与索引均无任何变化；
5. 在写入中途模拟失败后，环境与索引与安装前一致；
6. 目标已存在同名 Skill 时，未被静默覆盖。

### 3.6 FR-05 Skill 卸载

**需求描述**

用户必须能够卸载一个已管理的 Skill。卸载必须**只移除该 Skill 自身带来的文件**，不得影响其他 Skill 或用户的既有文件。

**关键要求**

1. **精确移除**：依据索引中记录的落位映射，逐个移除该 Skill 在中心库与各目标位置的文件；
2. **保护性默认**：卸载前必须生成备份并写入工作区的备份目录；中心库原件是否保留由参数决定，默认为保留；
3. **预演**：卸载必须支持预演模式，列出将被删除与将被保留的路径；
4. **一致性**：卸载完成后，索引中该 Skill 的记录必须被同步清理（或标记为已移除），不得留下悬空记录；
5. **失败可恢复**：卸载过程中失败时，必须能从备份恢复。

**验收标准**

1. 卸载后，该 Skill 的所有落位文件被移除；
2. 同一目标目录下其他 Skill 的文件未受影响（逐文件核对）；
3. 索引中不再存在指向已删除文件的记录；
4. 预演模式执行后无任何实际删除。

### 3.7 FR-06 Skill 启用

**需求描述**

用户必须能够启用一个已登记的 Skill，使其对目标位置生效。

**关键要求**

1. **状态为先**：启用首先体现为索引中该 Skill 的状态字段变更，索引是事实源；
2. **按需补齐**：状态变更后，确保目标位置存在该 Skill 所需的文件。文件已存在时**不重复分发**，仅在缺失时按该 Skill 的落位方式补齐；
3. **范围可控**：支持按目标位置选择性启用；未指定时使用默认目标；
4. **幂等**：对已启用的 Skill 重复执行启用不产生额外变更，并给出明确提示。
5. **前置校验**：运行期结论为「校验不通过」的记录不得被启用，须先修复其问题并重新扫描；拒绝时必须给出具体问题码，且**不得表述为「该 Skill 已被禁用」**，二者语义不同。

**验收标准**

1. 启用后索引状态为「启用」，且目标位置存在对应文件；
2. 重复启用不产生重复文件与错误；
3. 启用一个未登记的 Skill 时给出明确错误与修复建议；
4. 启用一个已落位的 Skill 时，不重复写入已存在的文件；
5. 启用一个以仅落库方式安装的 Skill 时，目标位置被补齐。
6. 对运行期结论为「校验不通过」的记录执行启用时被拒绝，返回其问题码，且提示文案不出现「已禁用」字样。

### 3.8 FR-07 Skill 禁用

**需求描述**

用户必须能够禁用一个已登记的 Skill，使其在目标位置不再生效，同时**保留 Skill 的全部文件与元信息**，以便随时恢复。

**关键要求**

1. **可逆**：禁用必须完全可逆，恢复后与禁用前状态一致；
2. **状态为先**：禁用首先体现为索引状态字段变更；落位层面必须在目标位置产生可被宿主识别的变化，使该 Skill 不再被视为可用；
3. **受控副本机制**：落位在目标位置的内容是内核维护的**受控副本**。启用与禁用只作用于该副本，**中心库原件与用户的源文件一律不改动**。一期统一采用副本内元数据文件改名的方式实现禁用：把副本内的技能元数据文件重命名为带禁用后缀的名称，宿主按既有发现规则不再将其识别为 Skill；启用时改回原名；
4. **不破坏结构**：禁用与启用不移动、不重命名、不删除任何目录，也不改变副本内文件之间的相对路径关系；
5. **可追溯**：索引中必须记录该 Skill 是被管理器禁用的，以便恢复时与「用户手动删除」区分；
6. **范围可控**：支持按目标位置选择性禁用。
7. **不触发分发**：禁用只切换该 Skill 在目标位置的可见性，不涉及内容分发，也不移除任何内容文件。

**验收标准**

1. 禁用后索引状态为「禁用」，且 Skill 目录与元数据文件仍然存在；
2. **禁用后，目标位置副本内的技能元数据文件已带禁用后缀；按宿主约定的发现规则，该 Skill 不再被识别为可用**；
3. 执行启用后，副本内文件名恢复原名，状态与文件恢复到禁用前的一致状态；
4. 禁用不删除任何 Skill 内容文件，中心库原件与用户源文件未被改动；
5. 禁用与启用往复操作后，副本内文件的相对路径关系保持不变。

### 3.9 FR-08 元数据与配置校验

**需求描述**

skill-manager 必须提供校验能力，覆盖三类对象：Skill 元数据文件、管理器配置文件、全局索引文件。

**元数据校验项（对齐通用规范）**

| 校验项 | 要求 |
|---|---|
| 字段白名单 | 只允许规范定义的字段；出现白名单外字段必须报告，并明确列出具体字段名 |
| 必需字段 | 名称与描述缺失即判定为不合规 |
| 名称格式 | 全小写、短横线分隔、不允许首尾短横线、不允许连续短横线、只允许字母数字与短横线 |
| 名称长度 | 不超过规范上限 |
| 目录名一致性 | 目录名必须与元数据中的名称一致 |
| 描述长度 | 不超过规范上限 |
| 兼容性字段 | 若存在必须为字符串且不超过规范上限 |
| 可解析性 | 元数据块必须可被正确解析；解析失败必须报错而非忽略 |

**配置与索引校验项**

| 校验项 | 要求 |
|---|---|
| 结构完整性 | 必需顶层字段齐全，类型正确 |
| 版本标识 | 索引版本号存在且被当前工具支持 |
| 引用有效性 | 索引中记录的路径、目标位置必须实际存在（禁用态除外） |
| 内容指纹 | 索引中记录的内容指纹必须与磁盘实际内容一致；不一致必须报告为「内容漂移」 |
| 一致性 | 索引与磁盘双向一致：无悬空记录，无未登记 Skill |

**输出要求**

1. 校验结果必须区分「错误」与「警告」两级；
2. 每条问题必须包含可定位信息（文件路径、字段名）与可执行的修复建议；
3. 校验过程必须只读，不得修改任何被校验对象。

**验收标准**

1. 使用正例与反例样本，全部反例均被检出且定位准确；
2. 对同一对象重复校验结果稳定；
3. 校验不产生任何写操作。

### 3.10 FR-09 依赖检查

**需求描述**

skill-manager 必须能解析 Skill 声明的依赖关系，并报告不满足项。

**一期支持的依赖类型**

| 类型 | 说明 |
|---|---|
| Skill 依赖 | 依赖其他 Skill，可带最低版本约束 |
| 运行环境依赖 | 依赖外部运行时及其最低版本 |

**检查要求**

1. **存在性检查**：被依赖对象是否已登记且校验通过。被依赖对象不在索引中，或其运行期结论为「校验不通过」时，依赖方一律判定为依赖未满足；
2. **版本检查**：已安装对象的版本是否满足声明的最低版本要求；
3. **完整性检查**：依赖关系是否存在环，环必须被检出并报告；
4. **影响面分析**：当某 Skill 被卸载或禁用时，必须报告有哪些其他 Skill 会因此受影响。

**约束**

一期**只检查、只报告，不自动安装**任何依赖。输出必须包含可直接执行的修复建议，由用户自行决定是否执行。

**验收标准**

1. 缺失依赖、版本不满足、依赖成环三类情形均能被检出；
2. 输出包含具体缺失项名称与建议操作；
3. 检查过程不产生任何安装行为。

### 3.11 FR-10 备份导出

**需求描述**

用户必须能够把当前的元信息与索引状态导出为一份可迁移的备份文件。

**备份内容要求**

1. 全局索引的完整内容；
2. 各 Skill 的元数据与来源信息；
3. 各 Skill 的状态与落位映射；
4. 内容指纹，用于导入时校验完整性；
5. 备份自身格式版本标识与导出时间。

**关键要求**

1. **敏感信息处理**：如备份内容涉及凭据、密钥等敏感配置，导出时必须剥离，并在备份中显式记录「已剥离项清单」；
2. **默认包含配置**：是否包含管理器配置由参数控制，默认为包含；
3. **可用性**：导出的备份不依赖绝对路径，需能在不同机器、不同用户目录下导入。

**验收标准**

1. 导出的备份文件可被同一工具在另一路径下成功解析；
2. 备份中不包含任何明文凭据；
3. 备份包含格式版本号，且能被工具识别。

### 3.12 FR-11 备份导入与恢复

**需求描述**

用户必须能够从备份文件恢复元信息与索引状态。

**关键要求**

1. **先校验后导入**：导入前必须校验备份格式版本、结构与内容指纹；校验失败必须整体拒绝，不得部分导入；
2. **预演**：导入必须支持预演模式，展示将新增、将覆盖、将冲突的条目；
3. **冲突策略显式化**：发生冲突时由用户显式选择保留旧值、采用备份值或两者并存，不得静默覆盖；
4. **不丢失本地改动**：若导入目标的实际文件与备份记录不一致，必须先报告「本地已修改」，由用户决定如何处理；
5. **原子性**：导入失败时环境必须保持导入前状态。

**验收标准**

1. 导出后立即导入，环境状态与导出前一致（往返一致）；
2. 篡改备份中的内容指纹后导入，被整体拒绝且环境无变化；
3. 冲突场景下未发生静默覆盖；
4. 预演模式执行后无任何实际写入。

### 3.13 FR-12 Skill 更新

**需求描述**

用户必须能够把已登记的 Skill 更新到其来源的较新版本，并保持索引与各落位目标的状态一致。

**关键要求**

1. **显式触发**：更新只能由用户显式发起，不得在后台自动执行。自动更新与后台升级属于二期范围；
2. **来源可解析**：仅当该 Skill 的来源类型为可解析来源（Git 仓库或归档文件）时才能执行更新；来源为本地目录或来源未知时，必须给出明确提示，不得静默跳过；
3. **本地漂移检测**：更新前必须比对该 Skill 当前内容与索引中记录的内容指纹；若磁盘内容已被本地修改，必须先报告「本地已修改」并由用户决定如何处理，不得静默覆盖；
4. **目标一致性**：更新完成后，该 Skill 已落位的所有目标必须一并更新，不得出现同一 Skill 在不同目标下内容不一致；
5. **失败可恢复**：更新失败时环境必须回到更新前的状态；
6. **预演**：更新必须支持预演模式，展示新旧差异与将发生的变更。

**验收标准**

1. 更新成功后，索引中的版本标识与内容指纹与被更新的内容一致；
2. 磁盘内容与索引记录不一致时，更新被阻止并给出明确提示；
3. 所有已落位目标的内容指纹在更新后保持一致；
4. 预演模式执行后无任何实际写入；
5. 来源不可解析的 Skill 被明确提示，且不产生任何变更。

### 3.14 一期明确不实现的功能

以下功能属于后续迭代范围，一期不实现，也不在一期进行设计：

1. 在线检索与市场接入（远端索引、一键安装社区 Skill）；
2. 分组、标签体系与预设批量启停；
3. 多 Agent 的自动分发与同步（跨目标批量部署、自动降级探测）；
4. 多设备协同、云端备份与冲突合并；
5. 对外 API 接口层（供 Agent 以函数方式调用的服务接口）；
6. 审计、统计与成本度量能力（使用统计、内容成本估算、触发可靠性评估）；
7. 包固化与可复现锁定快照（独立于索引的可复现锁文件）；
8. 自动更新与后台升级（后台自动拉取与变更合并）。用户显式触发的更新属于一期，见 FR-12。

## 4. 数据模型需求

### 4.1 技能元数据文件（SKILL.md）

每个 Skill 目录下必须存在一个技能元数据文件，其头部为结构化元数据块（YAML 形式），其后为指令正文。

**字段需求**

| 字段 | 必需 | 类型 | 需求说明 |
|---|---|---|---|
| 名称 | 是 | 字符串 | Skill 的唯一标识。全小写、短横线分隔、不超过规范长度、必须与所在目录名一致 |
| 描述 | 是 | 字符串 | 说明这个 Skill 做什么、在什么情况下使用。不超过规范长度 |
| 许可证 | 否 | 字符串 | 该 Skill 的许可协议标识 |
| 兼容性 | 否 | 字符串 | 该 Skill 适用的宿主或版本范围。不超过规范长度 |
| 允许工具 | 否 | 字符串 | 该 Skill 需要使用的工具范围 |
| 扩展元数据 | 否 | 键值映射 | 存放管理器的自研扩展字段（见下） |

**扩展元数据子字段需求**

| 子字段 | 必需 | 需求说明 |
|---|---|---|
| 版本 | 否 | Skill 自身的版本号 |
| 作者 | 否 | 作者或维护者标识 |
| 主页 | 否 | 来源或文档地址 |
| 标签 | 否 | 用于分类的标签列表 |
| 依赖声明 | 否 | 该 Skill 依赖的其他 Skill 与运行环境及其约束 |

**数据模型约束**

1. **不得在元数据块顶层新增自研字段**。所有管理器扩展字段必须收纳在扩展元数据映射之下，以保证与通用规范兼容；
2. 管理器必须对白名单外字段给出警告，并指明字段名，而不是静默接受或直接拒绝；
3. 元数据块必须保持人类可读、可被版本控制系统逐行比对；
4. 文件编码统一为 UTF-8。

### 4.2 管理器全局索引文件

skill-manager 必须维护一份全局索引文件，作为「已管理 Skill 集合」的唯一事实源。该文件由工具维护，允许用户阅读与手工微调（例如调整启用状态），但不保证手工编辑后的一致性，工具在校验时会报告漂移。

**顶层字段需求**

| 字段 | 必需 | 需求说明 |
|---|---|---|
| 索引版本 | 是 | 索引格式版本号。用于识别旧版本索引并决定是否需要迁移 |
| 工具版本 | 是 | 生成该索引的工具版本 |
| 生成时间 | 是 | 最近一次写入索引的时间 |
| 配置区 | 是 | 管理器的运行配置（见下） |
| Skill 记录区 | 是 | 所有已管理 Skill 的记录列表 |

说明：管理器的全局运行配置保留在索引文件的配置区内，工作区根目录不额外设立配置文件，因此全局配置的唯一位置就是本索引。该约定与 4.3 节的工作区目录布局一致。需要注意，配置区的内容无法由各 Skill 的元文件推导，因此删除索引会一并丢失全局配置，配置区必须随备份一同迁移。

**配置区字段需求**

| 字段 | 必需 | 需求说明 |
|---|---|---|
| Skill 根目录列表 | 是 | 发现 Skill 时要扫描的根目录集合 |
| 默认目标位置 | 否 | 未显式指定目标时使用的默认落位目标 |
| 默认落位方式 | 否 | 默认的文件落位方式标识 |

**Skill 记录字段需求**

| 字段 | 必需 | 需求说明 |
|---|---|---|
| 标识 | 是 | 唯一标识，取自元数据中的名称 |
| 名称 | 是 | 展示名称 |
| 描述 | 否 | 取自元数据 |
| 版本 | 否 | 取自扩展元数据 |
| 中心库路径 | 是 | 该 Skill 原件在中心库中的位置 |
| 状态 | 是 | 启用 / 禁用。此字段是启用状态的唯一事实源 |
| 来源类型摘要 | 是 | 仅记录来源类型。来源地址、引用标识与子路径的完整取值存于该 Skill 的元文件 |
| 许可证 | 否 | 取自元数据 |
| 标签 | 否 | 取自元数据 |
| 内容指纹 | 是 | 该 Skill 内容的一致性与完整性校验值。算法与计算范围见「派生区字段的取值规范」 |
| 依赖标识列表 | 否 | 仅记录被依赖 Skill 的标识；完整版本约束存于该 Skill 的元文件 |
| 落位目标摘要 | 是 | 仅记录目标标识、作用域与该目标下的启用状态；落位路径、落位方式与逐文件映射存于该 Skill 的元文件 |
| 校验结论 | 是 | 该 Skill 最近一次校验的结论与其问题明细。属于**运行期结论**，不是元文件的投影，仅由扫描动作写入 |
| 安装时间 | 否 | 首次登记时间 |
| 更新时间 | 否 | 最近一次变更时间 |

**来源信息（完整信息存于元文件，索引仅保留类型摘要）**

| 字段 | 必需 | 需求说明 |
|---|---|---|
| 来源类型 | 是 | 本地目录 / Git 仓库 / 归档文件 / 来源未知。四种取值之一 |
| 来源地址 | 条件必需 | 来源类型不是本地目录、也不是来源未知时必填 |
| 引用标识 | 条件必需 | 同上，记录分支、标签或提交标识 |
| 子路径 | 否 | 来源仓库内的具体子目录 |

说明：来源类型为来源未知时，来源地址与引用标识一并省略；来源类型为本地目录时二者亦省略。该规则与元数据规范的来源信息结构一致。

**落位目标（完整信息存于元文件，索引仅保留摘要）**

| 字段 | 必需 | 需求说明 |
|---|---|---|
| 目标标识 | 是 | 目标位置的标识名 |
| 作用域 | 是 | 全局级 / 项目级 |
| 落位路径 | 是 | 该 Skill 在该目标下的实际路径 |
| 落位方式 | 是 | 副本 / 链接。一期默认使用副本 |
| 启用状态 | 是 | 该目标下是否生效 |
| 禁用标记 | 是 | 该目标下的禁用实现方式。一期取值固定为「副本内技能元数据文件改名」，不得由用户逐目标自定义 |
| 文件映射 | 是 | 逐个文件的来源与落位对应关系。用于卸载时精确回收，避免误删 |

**索引的区域划分**

全局索引文件 `skill_index.yaml` 内部划分为三个区域，三者的可编辑性与维护责任不同：

| 区域 | 性质 | 维护方 |
|---|---|---|
| 声明区 | 由用户或安装流程显式声明，允许编辑 | 用户与安装流程 |
| 派生区 | 由系统自动计算生成，禁止用户手动修改 | 内核 |
| 运行期结论 | 由扫描动作计算生成，禁止用户修改，且不是元文件的投影 | 内核的扫描动作，且**仅限该动作** |

三个区域的差别在于信息来源：声明区与派生区都是元文件的投影或元文件的派生值；**运行期结论不来自元文件**，它是内核对当前环境状态的判定结果，因此随每次扫描重新计算，可以与上一次的取值不同。

**声明区字段需求**

| 字段键 | 对应本文档术语 | 必需 | 说明 |
|---|---|---|---|
| `id` | 标识 | 是 | 唯一标识，取自元数据中的名称 |
| `name` | 名称 | 是 | 展示名称 |
| `version` | 版本 | 否 | 取自元数据 |
| `description` | 描述 | 否 | 取自元数据 |
| `author` | 作者 | 否 | 取自元数据 |
| `license` | 许可证 | 否 | 取自元数据 |
| `status` | 状态 | 是 | 取值为 `enabled` 或 `disabled`，分别对应启用与禁用。此字段是启用状态的唯一事实源 |
| `path` | 中心库路径 | 是 | 该 Skill 原件在工作区中的位置 |
| `trigger_keywords` | 触发关键词 | 否 | 该 Skill 的触发关键词列表，用于检索与匹配 |
| `dependencies` | 依赖标识列表 | 否 | 仅记录被依赖 Skill 的标识；完整版本约束存于该 Skill 的元文件 |
| `source_type` | 来源类型摘要 | 是 | 仅记录来源类型。为满足列表展示而保留的引用摘要 |
| `targets` | 落位目标摘要 | 是 | 每项仅含目标标识、作用域与启用状态。为满足列表展示而保留的引用摘要 |

说明一：上表与本节前述的「Skill 记录字段需求」描述同一批字段，前者按记录视角罗列，本表按区域归属视角罗列，二者应当一致。

说明二：上表为索引保留的最小引用字段。来源信息与落位目标的**完整内容存于该 Skill 的元文件**，二者在元文件中属于声明区，由安装流程显式声明、允许编辑；索引中仅保留上表所列的摘要形式。索引与元文件的完整字段定义见元数据规范文档。

说明三：`source_type` 与 `targets` 两个摘要是为满足列表视图无需读取全部元文件即可展示来源类型与部署目标而保留的，属于引用投影，其权威来源仍是元文件。

**派生区字段需求**

| 字段键 | 对应本文档术语 | 必需 | 说明 |
|---|---|---|---|
| `created_at` | 安装时间 | 是 | 首次登记时间 |
| `updated_at` | 更新时间 | 是 | 最近一次变更时间 |
| `checksum` | 内容指纹 | 是 | 该 Skill 内容的一致性与完整性校验值 |

**派生区维护规则**

1. 派生区字段由内核在安装、更新、校验三个环节自动维护，用户不得手动修改；
2. 用户直接编辑派生区字段时，校验阶段必须给出**警告**，并指明被修改的字段名；
3. 派生区字段的计算结果不得作为任何配置的输入来源，仅用于一致性判断与结果展示。

**运行期结论的维护规则**

1. 运行期结论仅承载校验结论及其问题明细，表达该 Skill 当前是否存在契约违约、文件缺失或校验不通过；
2. **只有扫描动作可以写入或更新运行期结论**，其余全部指令一律不得改动；
3. 校验动作对运行期结论保持只读：它基于索引中已有的结论与实时的元数据读取出报告；结论已过期时，报告提示重新扫描，由校验动作自行改写的做法被禁止；
4. 运行期结论不是 Skill 的状态取值。启用与禁用仍只由状态字段表达，二者不得混用：**校验不通过不等于用户主动禁用**，反之亦然。

**派生区字段的取值规范**

1. **时间格式**：时间字段统一采用协调世界时的秒级标准格式，形如 `2026-10-12T04:03:58Z`；禁止使用本地时区偏移形式，禁止使用仅含日期的写法；更新时间不得早于安装时间；
2. **校验值算法**：内容指纹统一采用 SHA-256，以算法名加冒号加 64 位小写十六进制表示，例如 `sha256:` 后接十六进制串；
3. **校验值计算范围**：内容指纹覆盖该 Skill 目录内的全部普通文件，**但排除该 Skill 的元文件自身**，同时排除版本控制目录、备份文件与临时文件，且不跟随符号链接。排除元文件的原因是：若将其纳入范围，用户修改任一声明区字段都会触发内容漂移误报，声明区与派生区将无法共存；
4. **校验值缺失的判定**：内容指纹缺失或格式不合规属于错误级问题；内容指纹与磁盘内容不一致属于警告级问题，判定为内容漂移。

**索引最小化与 Skill 独立配置**

1. `skill_index.yaml` 只保存 Skill 的**引用元信息**，即上文所列的最小必要引用字段；**Skill 的完整配置不再嵌入索引文件**；
2. 各 Skill 的完整配置存放于该 Skill 独立目录下的 `skill_meta.yaml`，该文件称为该 Skill 的**元文件**，与 `SKILL.md` 同级；
3. 上述划分的目的是降低索引文件的膨胀速度，并降低并发写入时的冲突概率；
4. 索引引用字段、`skill_meta.yaml` 与 Skill 自身元数据块三者之间的权威来源与同步关系，见 4.3 节。

### 4.3 事实源与优先级

数据模型中必须明确以下优先级关系，避免出现两个互相冲突的事实源：

1. **启用状态的唯一事实源是索引中的状态字段**，文件系统层面的处理是派生结果，不是事实源；
2. **Skill 的标识与描述以元数据文件为准**，索引中的对应字段是其副本；
3. **来源与落位信息以元文件为准**；索引中仅保留二者的摘要形式，摘要与元文件不一致时以元文件为准，并报告为投影不一致；
4. **内容一致性以内容指纹为准**，指纹不一致即视为内容漂移，需要报告；
5. **索引的重建语义分两部分**：索引中的 Skill 记录区是元文件的投影，可完整重建，删除索引后可由各 Skill 的元文件与磁盘内容重新生成；索引顶层的配置区不可由元文件推导，删除索引会一并丢失全局运行配置。因此配置区与各 Skill 的元文件同为必须持久保存的内容，二者均随备份一并迁移。

**工作区文件布局**

工作区采用标准化目录布局，各路径的用途固定如下：

| 路径 | 类型 | 用途 |
|---|---|---|
| `skill_index.yaml` | 文件 | 全局索引，位于工作区根目录 |
| `./skills/` | 目录 | 每个 Skill 一个独立子目录，存放该 Skill 的 `skill_meta.yaml` 及其附属资源文件 |
| `./backups/` | 目录 | 破坏性操作前自动生成的备份，按操作时间分目录存放 |
| `./locks/` | 目录 | 并发写保护所使用的锁文件 |
| `./logs/` | 目录 | 运行日志，不包含明文凭据 |
| `./docs/` | 目录 | 项目文档 |
| `./spec/` | 目录 | 元数据规范 |

布局硬约束：

1. 每个 Skill 必须独占一个子目录，其元文件与附属资源一并存放于该目录内；
2. 不允许将多个 Skill 的元文件混放在同一目录；
3. Skill 与 `./skills/` 下的子目录保持一一对应。
4. 备份目录、锁目录与日志目录由管理器独占维护，用户不在其中手工组织内容；
5. 备份目录中的每次备份必须可按操作与时间回溯，且不得被后续操作静默覆盖；
6. 上述路径均为工作区内的相对路径，不得指向工作区之外的目录。

术语对应：本文档其他章节使用的「中心库」，即本节定义的 `./skills/` 目录。

根目录区分：本节所有路径均相对于**工作区根目录**，而不是仓库根目录。因此工作区内的 `./docs/` 与仓库侧的 `docs/` 是两个互不影响的目录；仓库侧的文档目录为 `docs/specification/`，与工作区内的 `./spec/` 亦不再重名。

**补充的优先级规则**

6. **三份产物的职责划分**：`SKILL.md` 的元数据块是该 Skill 对宿主可见的规范层元数据；`skill_meta.yaml` 是该 Skill 的管理器层完整配置，承载来源、落位、状态等管理器字段；`skill_index.yaml` 只保留二者的引用摘要，用于检索与列示，不作为配置的编辑入口；
7. **同名同义字段的权威来源**：名称、描述、版本、作者、许可证在索引声明区与 `skill_meta.yaml` 中均为引用副本，其权威来源是该 Skill 自身的元数据块；如需修改，应先修改 Skill 自身的元数据后重新同步，不得直接编辑索引；
8. **派生区字段的权威性**：派生区字段由内核维护，用户编辑不生效且会在校验阶段报告；派生区字段不得作为任何配置的输入来源。

### 4.4 数据模型约束

1. **单一索引文件**：一期只使用一份全局索引文件，不为每个 Skill 目录单独写入管理器私有索引文件；
2. **可读性**：索引文件必须保持人类可读，能被版本控制系统逐行比对；
3. **版本化**：索引必须带格式版本号，为后续迁移预留；
4. **可扩展**：新增字段时不得破坏旧版本索引的读取；未识别字段必须被保留而非丢弃；
5. **路径可移植**：索引中涉及用户目录的路径应相对于用户根目录表达，避免因换机器而失效；
6. **编码**：统一 UTF-8，兼容中文与含空格的路径。
7. **索引最小化**：索引只保留最小引用字段，不存储完整 Skill 配置。来源地址与引用标识、落位路径与落位方式、逐文件映射以及完整的依赖版本约束，一律存于该 Skill 的元文件；
8. **全局配置的唯一位置**：管理器的全局运行配置位于索引文件的配置区内，工作区根目录不额外设立配置文件；
9. **契约来源单一**：字段名称、数据类型、必填性与校验规则的正式定义以元数据规范文档为准，本节仅描述需求层面的约束。规范文档与本节不一致时，应先修订本节。
10. **工作区目录归属**：备份目录、锁目录与日志目录由管理器独占维护，其内容不参与索引与元文件的数据模型，也不作为任何配置的输入来源。

## 5. 交互指令需求

### 5.1 通用约定

| 约定项 | 要求 |
|---|---|
| 命名风格 | 统一为「管理器名 + 动作分组 + 动作」的形式；动作使用完整英文单词，不使用缩写 |
| 输出模式 | 默认人类可读文本；必须支持切换到机器可读结构，供 Agent 与脚本消费 |
| 预演 | 所有会改变磁盘或索引状态的指令必须支持预演模式，预演时不得产生任何实际变更 |
| 非交互 | 所有指令必须支持跳过交互确认，以适配自动化与 Agent 调用 |
| 幂等 | 重复执行同一条指令不得产生重复结果或错误（对已启用者再启用、对已登记者再登记等） |
| 失败原子性 | 指令失败时环境与索引必须保持执行前状态 |
| 错误提示 | 错误信息必须包含可定位信息与可执行的修复建议 |
| 无参数行为 | 直接执行管理器名且不带参数时，输出简要帮助与当前环境概要，不得自动执行任何写操作 |

### 5.2 指令清单（一期）

| 序 | 指令 | 作用 | 关键参数 | 阶段 |
|---|---|---|---|---|
| 1 | `skill-manager init` | 在指定位置初始化管理器工作区（建立索引与配置） | 作用域 | 一期 |
| 2 | `skill-manager config get` | 读取当前配置 | 机器可读输出 | 一期 |
| 3 | `skill-manager config set` | 修改配置（Skill 根目录列表、默认目标、默认落位方式） | 键、值 | 一期 |
| 4 | `skill-manager scan` | 发现当前环境中的 Skill 并刷新索引 | 根目录、预演 | 一期 |
| 5 | `skill-manager list` | 列出全部已管理 Skill | 状态过滤、来源过滤、目标过滤、机器可读输出 | 一期 |
| 6 | `skill-manager inspect <名称>` | 查看单个 Skill 的完整元信息与状态 | 机器可读输出 | 一期 |
| 7 | `skill-manager install <来源>` | 从受支持来源安装 Skill，登记并分发到目标位置 | 目标、作用域、落位方式、仅落库、预演、跳过确认 | 一期 |
| 8 | `skill-manager uninstall <名称>` | 卸载 Skill 并精确回收其文件 | 保留原件、预演、跳过确认 | 一期 |
| 9 | `skill-manager enable <名称>` | 启用 Skill；文件缺失时按需补齐，已存在时不重复分发 | 目标、作用域、预演 | 一期 |
| 10 | `skill-manager disable <名称>` | 禁用 Skill（保留文件与元信息，不触发内容分发） | 目标、作用域、预演 | 一期 |
| 11 | `skill-manager validate [路径或名称]` | 校验元数据 / 配置 / 索引；不带参数时校验整个环境 | 严格模式、机器可读输出 | 一期 |
| 12 | `skill-manager deps <名称>` | 检查依赖满足情况并报告影响面 | 依赖树视图、机器可读输出 | 一期 |
| 13 | `skill-manager export <文件>` | 导出元信息与状态备份 | 包含配置、剥离敏感信息 | 一期 |
| 14 | `skill-manager import <文件>` | 从备份文件导入并恢复 | 预演、冲突策略、跳过确认 | 一期 |
| 15 | `skill-manager update <名称>` | 从已登记来源更新 Skill；更新前检测本地漂移 | 目标、预演、跳过确认、全部更新 | 一期 |

### 5.3 输出契约要求

机器可读输出必须采用统一结构，至少包含下列内容：

| 内容 | 要求 |
|---|---|
| 执行结果 | 成功或失败标识 |
| 指令信息 | 本次执行的指令名与目标对象 |
| 问题列表 | 每条问题包含稳定问题码、严重级别、来源、目标、可读说明、修复建议 |
| 变更列表 | 本次实际发生的变更（新增 / 修改 / 删除的对象与路径） |
| 退出码 | 与执行结果一致的数值退出码 |

**要求**：问题码必须稳定，不得随文案调整而变化；修复建议必须是可被直接执行的指令形式。

### 5.4 退出码约定

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 通用失败或校验未通过 |
| 2 | 输入错误（参数、路径、名称不合法） |
| 3 | 索引或配置文件损坏、版本不受支持 |
| 4 | 远端操作失败 |
| 5 | 文件系统操作失败（含回滚后仍失败） |
| 6 | 依赖未满足 |

### 5.5 一期提供的交互形态与不提供的交互形态

一期提供两种交互形态，二者共用同一套指令与同一套内核能力：

1. **命令行模式**：可独立运行，不依赖图形外壳；
2. **桌面图形外壳**：只承担视图职责，不实现任何业务判定，所有操作均通过调用内核指令完成，移除该外壳不影响任何功能。

一期不提供的交互形态：

1. 交互式终端界面（TUI）；
2. 供外部程序调用的服务接口或函数接口；
3. 远端检索类交互（在线搜索、在线安装）。

## 6. 非功能需求

### 6.1 NFR-01 校验完备性

1. 校验必须覆盖元数据白名单、必需字段、命名规范、长度上限、目录名一致性、可解析性六类元数据问题；
2. 校验必须覆盖结构完整性、版本标识、引用有效性、内容指纹一致性、索引与磁盘双向一致性五类配置与索引问题；
3. 校验结果必须分级（错误 / 警告），且每条问题可定位到具体文件与字段；
4. 校验必须只读，任何情况下不得修改被校验对象。

### 6.2 NFR-02 稳定性与变更安全

1. **原子写入**：索引与配置的写入必须采用原子方式，避免写入中断导致文件损坏；
2. **自动备份**：卸载、导入等破坏性操作前必须自动备份并写入工作区的备份目录，备份可回滚；
3. **失败不改状态**：任何指令失败后，磁盘与索引必须与执行前一致；
4. **预演能力**：所有写操作必须支持预演，且预演必须真实反映将要发生的变更；
5. **并发保护**：索引与配置的并发写入必须有锁机制保护，锁文件统一存放于工作区的锁目录，避免互相覆盖；
6. **损坏容错**：索引损坏时不得崩溃，必须给出明确提示、保留损坏文件副本，并提供重建路径；
7. **幂等**：重复执行同一指令结果稳定。

### 6.3 NFR-03 兼容性

1. **规范兼容**：元数据模型必须与通用 Skill 规范保持一致，不自造顶层字段；
2. **宿主兼容**：不修改宿主 Agent 的私有配置语义；仅在宿主提供官方开关时使用官方开关；
3. **系统兼容**：支持主流桌面操作系统（Windows / macOS / Linux），不依赖特定平台的专有特性；
4. **离线可用**：核心能力在完全离线环境下必须可用；不依赖任何外部服务；
5. **路径兼容**：正确处理含空格、中文、非 ASCII 字符的路径；
6. **编码兼容**：统一 UTF-8，正确处理换行符差异。

### 6.4 NFR-04 可扩展性

1. **字段可扩展**：元数据新增信息必须通过扩展元数据映射承载，不破坏规范兼容性；
2. **索引可迁移**：索引必须带格式版本号，新版本工具读取旧索引时必须能识别并给出迁移方案；
3. **未知字段保留**：读取索引时遇到不认识的字段必须保留，不得丢弃；
4. **目标可扩展**：新增一个落位目标时，只应新增配置与适配描述，不应修改核心逻辑；
5. **来源可扩展**：来源类型必须设计为可扩展结构（类型 + 定位信息 + 引用标识），为后续新增来源类型预留；
6. **命令可扩展**：新增指令不得破坏既有指令的名称、参数与输出契约。

### 6.5 NFR-05 性能与规模

1. **扫描性能**：在单环境数百个 Skill 的规模下，一次完整登记应在秒级完成；
2. **查询性能**：单条查询与列表查询不得触发全量文件重新读取；
3. **索引体积**：索引文件体积应与 Skill 数量呈线性关系，不得引入冗余的大块内容；
4. **资源占用**：常驻内存占用应保持在轻量级，不引入重运行时依赖。

### 6.6 NFR-06 安全与隐私

1. **不执行第三方代码**：安装与卸载过程中不得执行被管理 Skill 内的任何脚本或可执行文件；
2. **不解释指令正文**：管理过程不得读取并执行 Skill 正文的指令内容；
3. **默认不联网**：除用户显式触发的远端操作外，默认不发起网络请求；
4. **不采集遥测**：不得收集或上报任何使用数据；
5. **敏感信息剥离**：导出备份时必须剥离凭据与密钥，并记录被剥离项；
6. **最小权限**：只读写自身工作区与用户显式指定的目标位置，不触碰系统目录。

### 6.7 NFR-07 可观测性与错误处理

1. 所有指令必须提供稳定的机器可读输出与稳定的退出码；
2. 错误信息必须包含：问题码、发生位置、可读说明、修复建议；
3. 详细日志与错误日志必须分离并写入工作区的日志目录，且日志中不得包含明文凭据；
4. 必须提供自检能力，用于报告环境异常（缺失目录、失效记录、内容漂移、依赖缺失）。

### 6.8 NFR-08 可维护性与文档

1. 必须提供与本文档配套的规范说明与字段定义文档；
2. 必须提供正例与反例样本，供校验能力的回归测试使用；
3. 每条指令必须提供内置帮助，说明用途、参数与示例；
4. 必须维护变更记录，明确标注哪些功能属于一期、哪些属于后续迭代。

## 7. 项目边界与排除项

### 7.1 边界总原则

**skill-manager 只管理 Skill 的元信息与文件编排，不执行任何被管理 Skill 的业务逻辑。**

这条原则是所有边界判断的依据：任何需求，只要能归入「读取元信息、校验元信息、维护索引、控制文件位置与可见性」，就属于本项目；任何需求，只要需要「运行、调用、解释、编排 Skill 的实际能力」，就不属于本项目。

### 7.2 职责边界对照

| 事项 | 是否属于本项目 | 说明 |
|---|---|---|
| 读取与解析 Skill 的元数据块 | 属于 | 只读取结构化元数据 |
| 校验元数据是否合规 | 属于 | 只做格式与约束校验 |
| 维护已安装 Skill 的清单索引 | 属于 | 元信息层 |
| 控制 Skill 文件的安装与移除 | 属于 | 文件编排，不执行内容 |
| 控制 Skill 的启用与禁用 | 属于 | 控制可见性，不改变内容语义 |
| 检查依赖声明是否满足 | 属于 | 只检查与报告 |
| 元信息的备份与恢复 | 属于 | 只涉及元信息与索引 |
| 读取并执行 `SKILL.md` 正文中的指令 | 不属于 | 属于宿主 Agent 的职责 |
| 运行 Skill 目录内的脚本或可执行文件 | 不属于 | 属于业务逻辑执行 |
| 调用模型或服务来完成 Skill 描述的任务 | 不属于 | 属于 Agent 运行时 |
| 自动安装缺失的依赖 | 不属于 | 一期只报告不执行 |
| 托管或索引公网上的 Skill | 不属于 | 属于市场接入，二期范围 |
| 提供 IDE 内的插件宿主能力 | 不属于 | 属于 IDE 插件系统 |
| 修改宿主 Agent 的私有配置格式 | 不属于 | 仅使用宿主官方开关 |

### 7.3 明确不做的功能

以下功能本项目不负责实现，也不应被后续提交以「顺手加上」的名义纳入一期：

1. **不执行 Skill 业务逻辑**：不加载、不调用、不运行任何被管理 Skill 的脚本、提示词、工具或服务；
2. **不解释 Skill 正文**：不解析 `SKILL.md` 正文中的指令语义，只处理头部元数据块；
3. **不充当 Agent 运行时**：不管理对话、上下文、模型调用、工具调度；
4. **不做市场与分发**：不托管 Skill 内容、不提供在线检索、不提供一键安装社区 Skill；
5. **不做内容编辑**：不提供 Skill 内容的撰写、修改、生成能力；
6. **不做自动更新**：不实现后台自动升级与变更合并；更新只能由用户显式触发；
7. **不做跨设备协同**：不实现云端备份、多机同步、冲突合并；
8. **不做服务化接口**：不提供常驻服务、网络端口或函数级对外接口；
9. **不管理非 Skill 类扩展**：一类只管理以 Skill 形态存在的资产（含元数据文件的目录），不管理 MCP 服务、钩子、插件二进制等其他扩展类型；
10. **不做依赖自动安装**：只检查与报告；
11. **不做安全审计与合规扫描**：一期不实现安全扫描、风险评估与合规检查。

### 7.4 范围膨胀防护机制

1. **需求准入**：任何新增功能请求必须首先判定其属于一期还是后续迭代；属于后续迭代的，一律登记入待扩展清单，不在本文档中展开设计；
2. **边界自检**：评审新需求时，先回答「它是否需要运行、解释或编排 Skill 的实际能力」，答案为「是」即超出本项目边界；
3. **拒绝「顺手实现」**：不接受以参数、隐藏开关或实验特性形式夹带的范围外功能；
4. **文档同步**：若边界发生变更，必须先更新本文档的边界章节，再进入实现；
5. **一期冻结**：一期进入实现阶段后，本文档第 3 章的功能清单即冻结，新增项默认进入后续迭代。

## 8. 风险与约束说明

### 8.1 风险清单

| 编号 | 风险描述 | 影响 | 应对措施 |
|---|---|---|---|
| R-01 | 通用 Skill 规范仍在演进，元数据字段定义可能变化 | 校验规则与数据模型过时，导致误报或漏报 | 校验规则版本化；对白名单外字段只警告不拒绝；在扩展元数据映射中承载自研字段，避免与规范耦合 |
| R-02 | 不同宿主 Agent 的 Skill 目录约定不一致，且部分缺少公开文档 | 扫描不到 Skill，或扫描到非预期目录 | 目录集合完全配置化；对无法识别的目录给出提示而非报错；提供自检能力报告异常 |
| R-03 | 启用与禁用的落地方式在不同宿主上行为不一致 | 用户预期与实际效果不符 | 以索引状态字段作为唯一事实源；落地方式由实现决定但必须可逆且不破坏内容；在输出中明确说明实际执行的动作 |
| R-04 | 文件落位方式涉及符号链接，跨平台差异大（权限、跟随行为） | 在部分平台或宿主上 Skill 不可见 | 一期默认使用副本方式；链接方式与自动能力探测推迟到后续迭代 |
| R-05 | 卸载或覆盖操作误删用户文件 | 数据丢失，信任受损 | 索引中维护逐文件映射以精确回收；卸载与导入前强制备份；默认保留中心库原件；提供预演模式 |
| R-06 | 更新或导入时覆盖用户对 Skill 的本地修改 | 本地改动静默丢失 | 通过内容指纹检测内容漂移；发现漂移必须先报告并由用户决定；不静默覆盖 |
| R-07 | 索引文件并发写入导致内容损坏或互相覆盖 | 状态丢失，索引不可用 | 写入加锁；原子写入；保留损坏文件副本；支持从元数据重建索引 |
| R-08 | 索引中记录绝对路径，换机器后全部失效 | 备份无法跨环境恢复 | 路径相对于用户根目录表达；备份内容不依赖绝对路径 |
| R-09 | 来源信息缺失导致 Skill 无法被追溯与维护 | 无法评估可信度与更新需求 | 引入「来源未知」状态作为一等状态，并引导用户补全来源 |
| R-10 | 用户手工编辑索引造成与磁盘不一致 | 状态错乱，操作结果异常 | 校验能力覆盖索引与磁盘的双向一致性，并报告漂移 |
| R-11 | 一期外功能被持续塞入，导致范围膨胀、主线延期 | 一期无法交付 | 执行第 7.4 节的范围膨胀防护机制 |
| R-12 | 安装阶段被要求执行第三方脚本（供应链风险） | 安全事件 | 明确禁止执行；安装只做元数据读取、文件落位与静态校验 |
| R-13 | 各宿主对元数据的容错程度不同，宽松解析可能被误判为不合理 | 合规的 Skill 被误报为不合规 | 校验分级（错误 / 警告）；区分「规范强制项」与「建议项」 |

### 8.2 约束条件

| 类别 | 约束 |
|---|---|
| 规范约束 | 元数据模型必须与通用 Skill 规范保持一致，不得在元数据块顶层自造字段 |
| 范围约束 | 只管理元信息与文件编排；不执行被管理对象的能力 |
| 阶段约束 | 一期只实现本文档第 3 章列出的功能；其余一律推迟 |
| 依赖约束 | 核心能力必须离线可用，不依赖外部服务；不引入重型运行时 |
| 平台约束 | 需在 Windows / macOS / Linux 上可用，不得依赖单一平台专有特性 |
| 数据约束 | 索引必须人类可读、可被版本控制系统逐行比对；必须带格式版本号 |
| 变更约束 | 破坏性操作必须有备份与回滚路径；必须支持预演 |
| 安全约束 | 不执行第三方代码；不采集遥测；导出时剥离敏感信息 |
| 交付约束 | 一期交付物包含：需求文档、规范说明、字段定义、正反例样本、使用说明 |

### 8.3 假设与前置条件

1. 目标环境中已存在若干以「含元数据文件的目录」形式存在的 Skill；
2. 宿主 Agent 允许通过文件系统层面的操作控制 Skill 的可见性；
3. 用户拥有对相关目录的读写权限；
4. 用户能够提供或确认 Skill 的来源信息（无法提供时以「来源未知」状态登记）；
5. 一期不要求工具在运行期与宿主 Agent 建立进程级协作，双方只通过文件系统交互。

## 附录 D 一期功能冻结声明

### D.1 冻结范围

自本声明起，下列内容进入冻结状态：

| 冻结对象 | 内容 |
|---|---|
| 功能需求 | FR-01 至 FR-12，共十二条 |

| 数据模型 | 元文件与索引的字段定义、三个区域的划分、运行期结论的写入权限 |
| 对外契约 | 结果封装结构、问题码表与退出码取值 |

### D.2 冻结的含义

1. 冻结不等于不可修改。勘误、澄清与表述一致性的修订仍可进行，但须走变更记录中的批次登记；
2. 改变语义、增删字段、增删指令、调整取值范围属于**变更**，不属于勘误；
3. 任何变更必须先更新本文档与对应契约，经评审后再进入实现，**不得先改实现再补文档**；
4. 冻结的目的是把变更成本锁定在文档阶段，避免实现与需求脱节。

### D.3 变更的登记要求

1. 每次变更在受影响文档的变更记录中登记为独立批次，逐条记录改动前与改动后；
2. 一次修订涉及多份文档时，各文档分别登记，不得只在一处记录；
3. 涉及批量修订的，须逐条回执，并在批次结束后按清单复核；
4. 契约版本号随不兼容变更递增，兼容性分级见元数据规范第 7.2 节。

### D.4 解冻与二期

二期功能的立项不属于本次冻结范围。二期待定的能力已在第 3.14 节与附录 B 中登记，其立项需单独评审。
