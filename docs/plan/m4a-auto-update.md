## 0.1 计划期事实与口径（先定，避免实现时再猜）

| # | 事实 | 处置 |
|---|---|---|
| F-1 | `updateSkill` 只在「git/archive **且声明了 `location`**」时 refetch；远端形式（`url` + `ref`）只按磁盘刷新（`kernel/core/lifecycle/index.ts:1144-1160`） | T0 修复：refetch 条件改为「git/archive 且（`location` 或 `url`）」，`acquireSource` 传入 `location ?? url`；`source.ts` 已用 `looksRemote()` 自动识别远端，无需新下载实现 |
| F-2 | 协议白名单：`https` / `git`，`http` 仅限回环地址；**`file://` 被拒绝**（`source.ts:72-88`） | T0 的端到端用例用**本机回环 http 的 git 仓库**（或注入执行器）；不得用 `file://` 绕过 |
| F-3 | `source.ts` 顶部注释仍写「本批次不接受远程来源」（占位残留） | T0 一并更正注释（代码事实与注释一致） |
| F-4 | `inspect <id>` 的输出载荷已含「来源信息的完整取值」（契约 4.6） | T1 的检查数据源走 **`inspect <id> --json`**（内核只读），GUI 不自行解析工作区路径 |
| F-5 | 分层约束：界面不得引用内核内部模块 | GUI 侧自建常量（60 s / 128 MiB / `E-SRC-*` 文案）＋**契约测试**读取内核源码断言数值一致（机械锁，不做跨层 import） |
| F-6 | GUI 无设置持久化 | 定期开关写入 GUI 的 `userData` 设置文件（**切换时写**）；**检查动作本身零写入**（两件事分开登记） |
| F-7 | 四态 + provenance + 备份提示的字段形状已在设计 3.1 定稿 | T1 按该形状产出；T2 只做展示与执行接线 |

## 1. 任务序列

### T0 契约修订与远端 refetch（前置批次）

**执行状态**：待开始。

**目标**：把 `update` 的远端来源从「二期占位」兑现为可用能力，并先改契约再改实现。

**依赖**：设计定稿（七项裁决）。

**交付物**：

1. **契约 4.11 修订（先于代码）**：删除「远端拉取属二期 / 本批次返回 `E-SRC-001`」的占位表述，改为「git/archive 来源（本地或远端）均重新获取并替换原件」；**保留**「本地来源的语法、参数、输出与刷新语义不变」的声明；补「远端获取沿用既有超时（60 s）与体积上限（128 MiB）」「获取失败按 `E-SRC-*` 返回且不写索引」；
2. 需求侧澄清批次：M4a-R5 的「行为不变」注明「远端来源从占位转为兑现，不改变任何调用方式」；
3. `updateSkill` 的 refetch 条件与来源解析（F-1）；`source.ts` 注释更正（F-3）；
4. 既有「按磁盘刷新」的占位断言更新（远端来源原断言 `E-SRC-001`，改为「可 refetch」）；
5. 测试：远端 refetch 端到端（回环 http 的 git 仓库：安装 → 原仓库推进提交 → `update` → 内容与指纹更新；失败路径不写索引）。

**验收标准（可验证）**：

1. 契约 4.11 通读无「二期 / 占位」残留，且明确本地来源行为不变；
2. 远端 git 来源：`update` 后中心库原件内容与记录指纹均更新（用真实回环 http git 仓库验证）；
3. 远端获取失败（断网/404/超限）：退出码 4、不写索引（前后索引字节一致）；
4. 本地来源行为回归：本地 git/归档、`--check`、`--target`、`--host` 的既有用例全绿且语义不变；
5. 既有测试不回归，门禁零告警。

**规模估算**：1 处契约修订 + 1 处需求澄清 + 2 个源文件小改 + 端到端用例 3~5 条；不新增依赖。

**风险与处置**：回环 http git 服务在 CI 上的可用性 → 优先用 `git daemon`/`http-backend` 的最小封装，不可行则用**注入执行器**覆盖逻辑并以本机实测补一条真机证据（登记结论）。

### T1 检查能力（纯函数 + 注入数据源）

**执行状态**：待开始。

**目标**：把「四态判定」做成与 UI 解耦、可单测的纯逻辑，并保证检查只读。

**依赖**：T0（远端来源可执行，才谈得上「可更新→执行」闭环）。

**交付物**：

1. `gui/main/update-check/` 模块：
   - `parseLsRemote(text)`：解析 `git ls-remote` 输出（ref → commit）；
   - `selectLatestFormalTag(tags)`：只保留 semver **正式版**，取最高；
   - `classify(item)`：四态判定（裁决 7 的规则；基线 `ref` 标签优先、回退元文件 `version`）；
   - `checkUpdates({ items, probe, now })`：注入式 `probe`（git ls-remote / HEAD），单条失败不阻断；
   - 结果形状：`{ command: 'update-check', ok, findings, data: { checked_at, items } }`（含 provenance 与 `backup_notice`）；
2. 数据源：`inspect <id> --json`（内核只读）取来源完整取值；本地/未知来源直接归 `not-checkable`（带原因）；
3. 常量与文案：60 s / 128 MiB / `E-SRC-*` 映射；**契约测试**读取内核源码断言数值一致（F-5）；
4. 测试：标签解析、semver 比较（含 prerelease 排除、非 semver 标签、相同/更高/更低）、四态矩阵、单条失败不阻断、`probe` 超时与 401/403→`E-SRC-010`、**只读断言**（检查前后索引与工作区文件字节不变）。

**验收标准（可验证）**：

1. 四态全部可达且各有单测（可更新 / 已最新 / 不可检查 / 失败）；
2. 基线规则逐条可测：`ref` 为 semver 标签 → 以它为基线；无 semver `ref` → 用元文件 `version`；两者都没有 → `not-checkable`；
3. prerelease 与非法标签**不参与**比较（反例断言：远端只有 prerelease 时不得报「可更新」）；
4. 检查零写入：检查前后 `skill_index.yaml` 与 `skills/**` 的字节/数量不变；
5. 失败口径与内核一致（`E-SRC-006` 超时、`E-SRC-010` 认证/限流、`E-SRC-002/007` 失败）；
6. 既有测试不回归，门禁零告警。

**规模估算**：1 个模块目录 + 4~6 个测试文件；不新增运行时依赖（`git` 由用户环境提供，缺失时归 `E-SRC-005`）。

**风险与处置**：`git` 不存在时的降级 → 该项 `failed` + `E-SRC-005`（命令不可用），其余项继续；不自动下载 git。

### T2 GUI 接线（入口、四态展示、执行、设置）

**执行状态**：待开始。

**目标**：把检查能力接到外壳，执行走既有 `update`，并落实频率开关。

**依赖**：T1。

**交付物**：

1. 主进程 IPC：`updates:check`（只读检查）与 `updates:update`（仅转发既有 `update` 通道，不新增写入路径）；preload 暴露类型化 API；
2. 渲染层：工具栏「检查更新」按钮 + `UpdateCheckDialog.vue`（四态分组；`not-checkable` 与失败必须有可读原因，不得只显示码）；
3. 执行：逐项「更新」按钮 → 既有「预览 → 确认 → `--yes`」流程（`update <id> --yes`）；「全部更新」逐项执行、单条失败不阻断；执行后刷新列表；
4. 设置：定期检查开关（默认关闭，最小 6 小时，仅运行期间）；即时检查开关（默认关闭）；到期不做静默执行；
5. 测试：主进程检查的 IPC 契约、渲染层四态渲染（含不可检查文案）、确认后只调用 `update`（不出现新的写命令）、开关下限校验、**应用关闭时无定时器**（可断言无注册）。

**验收标准（可验证）**：

1. 手动检查入口可用，四态展示与设计一致；
2. 未确认时无任何写调用（可用 bridge 调用记录断言）；
3. 确认后调用的是既有 `update` 指令（参数含 `--yes`），逐项失败不阻断；
4. 定期开关默认关闭；开启后周期 ≥ 6 小时；关闭后无定时器；应用不在运行时不产生任何活动；
5. 本地来源条目显示「不可检查：本地来源无新版本概念，请用 `update --check`」（裁决 6）；
6. 既有测试不回归，门禁零告警。

**规模估算**：1 个 IPC 通道组 + 1 个对话框组件 + 工具栏/设置改动 + 5~8 条测试；不新增依赖。

**风险与处置**：GUI 端到端在 CI 上无窗口 → 主进程逻辑用单元测试（注入 bridge），渲染层用组件级断言；真机窗口冒烟沿用 `smoke:gui` 登记结论。

### T3 收口（端到端、口径、文档）

**执行状态**：待开始。

**目标**：闭环远端 refetch 与检查的端到端证据，并同步文档与计数。

**依赖**：T0 ~ T2。

**交付物**：

1. 端到端：远端 git 来源「安装 → 检查（可更新）→ 确认 → `update` → 检查（已最新）」完整链路（回环 http git 仓库或注入执行器 + 本机真机证据）；
2. 失败矩阵：离线、限流（403）、认证（401）、超时、命令缺失（无 git）逐项断言；
3. 只读与无后台：检查阶段零写入、无定时器注册（关闭时）、无静默执行（可复核）；
4. 文档：`one-summary`（7.4 M4a 状态、4.1 规模刷新）、CHANGELOG、需求回写批次与计数校验；**M4a-2 登记**（应用自更新：签名为前置，不排期）；
5. 契约与设计回写：契约 4.11 终态、设计第 5 节六项决策回填裁定结果。

**验收标准（可验证）**：

1. 端到端链路逐段落证据（命令、退出码、内容/指纹变化、检查结果 JSON）；
2. 失败矩阵逐项有码与可读文案，且均不阻断其他项；
3. 检查只读断言与「无后台定时器」断言通过；
4. 文档与计数同步；`docs/reviews/` 快照与一期/二期定稿未动；
5. 全量测试与门禁全绿。

**规模估算**：3~5 条端到端用例 + 文档批次；不新增功能。

## 4. 硬性约束与执行纪律

1. **先文档后实现**：契约 4.11 的修订先于 T0 代码；需求澄清批次同步登记；
2. **不新增指令**（16 条）、不新增运行时依赖（`git` 缺失按 `E-SRC-005` 处理）；
3. **检查只读**：不写索引、不写运行期结论、不改工作区文件；「写设置文件」只发生在用户切换开关时；
4. **无后台静默**：应用未运行不检查；未开启开关不检查；任何检查不自动执行更新；
5. **分层**：界面不得引用内核内部模块；跨层常量由契约测试比对（F-5）；
6. 门禁以退出码判定；用例数核对沿用；`docs/reviews/` 与一期/二期定稿不动。
