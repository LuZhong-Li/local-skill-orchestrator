## 1. 文档概述

### 1.1 目的

本规范定义三件事：

1. 每条指令执行完毕后，对外返回的**统一结果封装**结构；
2. 结果中承载问题的**问题码**编码规则与登记表；
3. 指令结束后返回的**退出码**取值与派生规则。

本规范是命令行输出、界面呈现与自动化集成的共同依据。任何指令的返回都必须满足本规范。

### 1.2 适用范围

| 属于本规范范围 | 不属于本规范范围 |
|---|---|
| 结果封装的字段与结构 | 各指令的具体参数与行为，见指令契约规范 |
| 问题码的编码规则与取值 | 元数据字段的校验规则，见元数据规范 |
| 严重级别与退出码的定义与映射 | 索引文件自身的结构，见索引格式规范 |
| 三种输出通道的等价性要求 | 界面的视觉呈现与交互细节 |

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| **结果封装** | 指令执行完毕后返回的统一结构，包含执行结果、指令信息、问题列表、变更列表与退出码 |
| **findings** | 结果封装中的问题列表，每条承载一个问题码与一条可执行的修复建议 |
| **changes** | 结果封装中的变更列表，记录本次实际发生的新增、修改与删除 |
| **问题码** | 标识问题类型的稳定编码，不随文案调整而变化 |
| **严重级别** | 问题的分级，取值为错误或警告 |
| **退出码** | 进程结束后返回给调用方的数值状态码 |
| **视图数据载荷** | 查询类指令在结果封装中额外携带的业务数据 |

## 2. 结果封装结构

### 2.1 顶层字段

每条指令的结果封装必须包含下列字段。缺省的可选字段允许省略，但不得改变语义。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ok` | 布尔 | 是 | 执行结果。无错误级问题时为真，否则为假 |
| `command` | 字符串 | 是 | 本次执行的指令名，与指令契约中的名称完全一致 |
| `id` | 字符串 | 否 | 本次操作的目标对象标识，批量操作时省略 |
| `findings` | 数组 | 是 | 问题列表。无问题时为空数组，不得省略 |
| `changes` | 数组 | 是 | 变更列表。无变更时为空数组，不得省略 |
| `exit_code` | 整数 | 是 | 与 `ok` 一致的退出码，取值见第 5 章 |
| `data` | 对象 | 否 | 视图数据载荷，仅查询类指令携带 |
| `request_id` | 字符串 | 否 | 调用方提供的请求标识，用于配对请求与响应 |

### 2.2 字段约束

1. `findings` 与 `changes` 必须是数组，即使为空也必须是空数组，以保证调用方无需做空值判断；
2. `exit_code` 必须与 `ok` 一致：`ok` 为真时取值为 `0`，`ok` 为假时不得为 `0`；
3. `command` 必须使用指令的规范名称，不使用别名；
4. 可选字段缺失时直接省略该键，不写入空值；
5. 预演模式下实际未产生变更，`changes` 记录的是**将要发生**的变更，且必须在结果中标注本次为预演。

### 2.3 preview 标记

预演结果必须额外携带一个标记字段，使调用方能够区分「已执行」与「仅预演」。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `preview` | 布尔 | 条件必填 | 仅为预演时为真；实际执行时必须省略或为假 |

### 2.4 findings 条目结构

每条问题必须包含下列字段，字段齐全性由契约保证，不得出现只有说明没有修复建议的条目。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | 字符串 | 是 | 问题码，取值见第 4 章 |
| `severity` | 字符串枚举 | 是 | 严重级别，仅允许 `error` 或 `warning` |
| `source` | 字符串 | 是 | 问题来源标识，用于定位，例如 `registry`、`meta`、`input`、`system` |
| `target` | 字符串 | 是 | 问题指向的对象，例如 Skill 标识、目标位置或字段名 |
| `message` | 字符串 | 是 | 一行可读说明，面向使用者 |
| `remedy` | 字符串 | 是 | 可直接执行的修复建议，通常为一条指令形式 |

约束：

1. `code` 必须稳定，文案调整不得改变问题码；
2. `remedy` 必须是可直接执行的动作，不得使用「请检查配置」这类无法执行的表述；
3. 涉及具体字段的问题，`target` 必须指明字段名；
4. 同一问题重复出现时逐条列出，不合并计数。

### 2.5 changes 条目结构

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `action` | 字符串枚举 | 是 | 变更类型，仅允许 `add`、`modify`、`remove` |
| `kind` | 字符串枚举 | 是 | 变更对象类别，例如 `meta`、`index`、`target_file`、`library_file`、`backup` |
| `path` | 字符串 | 是 | 变更对象的路径 |
| `detail` | 字符串 | 否 | 补充说明，例如原值与新值 |

## 3. 严重级别

| 级别 | 取值 | 含义 | 对执行结果的影响 |
|---|---|---|---|
| 错误 | `error` | 契约被破坏，管理器无法保证行为正确 | 对应指令的操作被阻断；`ok` 为假；校验类指令以非零退出码结束 |
| 警告 | `warning` | 不阻断使用，但需要用户关注 | 操作可以继续；`ok` 仍为真；退出码为 `0` |

级联规则：

1. `findings` 中只要存在一条错误级问题，`ok` 必须为假；
2. 仅有警告级问题时，`ok` 为真，退出码为 `0`；
3. 警告级问题不得导致操作被阻断；
4. 校验类指令退出码为 `1` 的条件是存在错误级问题，存在警告不构成退出码 `1`。

## 4. 问题码规范

### 4.1 编码规则

问题码采用三段式：**级别字母、类别、三位序号**，以短横线连接，全大写。

| 段位 | 取值 | 说明 |
|---|---|---|
| 级别字母 | `E` 或 `W` | `E` 表示错误级，`W` 表示警告级。级别字母必须与该条问题的 `severity` 一致 |
| 类别 | 见 4.2 节 | 表示问题所属的领域 |
| 序号 | 三位数字，从 `001` 起 | 在同一类别内唯一，一经分配不再复用 |

示例：`E-ID-002` 表示标识类别的第二号错误级问题。

### 4.2 类别表

| 类别 | 含义 |
|---|---|
| `INPUT` | 调用方传入的参数问题 |
| `FIELD` | 元数据或索引中的字段问题 |
| `ID` | Skill 标识的命名与唯一性问题 |
| `STATUS` | 启用状态取值问题 |
| `VALIDATION` | 校验不通过引发的拒绝与依赖不可用 |
| `TIME` | 时间字段问题 |
| `HASH` | 内容指纹的格式与缺失问题 |
| `DRIFT` | 内容漂移 |
| `YAML` | 文件语法与序列化问题 |
| `DEP` | 依赖相关问题 |
| `RUN` | 外部运行时的探测结论（环境相关，不入索引） |
| `CONFLICT` | 命名、落位与占用冲突 |
| `PATH` | 路径可达性与越界问题 |
| `INDEX` | 索引自身的一致性与生命周期问题 |
| `SRC` | 来源可解析性问题 |
| `VER` | 版本兼容性问题 |
| `LOCK` | 并发锁问题 |
| `IO` | 文件系统读写问题 |
| `BAK` | 备份的写入与校验问题 |
| `ENV` | 工作区与环境问题 |
| `CHANNEL` | 宿主调用通道问题 |

#### 元数据与索引类（对应元数据规范的校验规则）

| `E-ID-001` | 错误 | Skill 标识不符合命名规范 |
| `E-ID-002` | 错误 | Skill 标识在工作区内重复 |
| `E-ID-003` | 错误 | Skill 标识与所在目录名不一致 |
| `E-TIME-001` | 错误 | 时间字段格式不合规 |
| `E-TIME-002` | 错误 | 时间先后关系不成立 |
| `E-HASH-001` | 错误 | 内容指纹缺失或格式不合规 |
| `E-HASH-002` | 错误 | 参与校验的内容全部缺失 |
| `W-DRIFT-001` | 警告 | 内容指纹与磁盘内容不一致，判定为内容漂移 |
| `E-YAML-001` | 错误 | 文件违反 YAML 基础约束或无法解析 |
| `E-FIELD-001` | 错误 | 必填字段缺失 |
| `E-FIELD-002` | 错误 | 字段取值不在允许范围内 |
| `E-FIELD-003` | 错误 | 字段长度超出上限 |

#### 依赖类

| 问题码 | 级别 | 含义 |
|---|---|---|
| `E-DEP-001` | 错误 | 被依赖的 Skill 不存在 |
| `E-DEP-002` | 错误 | 依赖版本不满足约束 |
| `E-DEP-003` | 错误 | 依赖关系成环 |

### 4.4 校验规则与问题码的对应

元数据规范第 5.8 节的校验规则总表与本规范的问题码必须一一对应，对照关系如下。

| 校验规则 | 规则名称 | 问题码 |
|---|---|---|
| V-01 | Skill ID 命名合规 | `E-ID-001` |
| V-02 | Skill ID 全局唯一 | `E-ID-002` |
| V-03 | Skill ID 与目录名一致 | `E-ID-003` |
| V-04 | 时间格式合规 | `E-TIME-001` |
| V-05 | 时间先后关系 | `E-TIME-002` |
| V-06 | 校验值格式合规 | `E-HASH-001` |
| V-07 | 内容一致性 | `W-DRIFT-001` |
| V-08 | 内容缺失判定 | `E-HASH-002` |
| V-09 | YAML 基础约束 | `E-YAML-001` |
| V-10 | 必填字段完整性 | `E-FIELD-001` |
| V-11 | 字段取值域与长度 | `E-FIELD-002`、`E-FIELD-003`、`E-FIELD-005` |
| V-12 | 依赖存在与版本满足 | `E-DEP-001`、`E-DEP-002` |
| V-13 | 依赖成环检测 | `E-DEP-003` |
| V-14 | 派生区篡改检测 | `W-DERIVED-001` |
| V-15 | 启用状态枚举 | `E-STATUS-001` |
| V-16 | 跨文件投影一致性 | `W-INDEX-001` |
| V-17 | 引用路径可达性 | `E-PATH-001` |
| V-18 | 索引版本受支持 | `E-VER-001` |

V-11 覆盖取值域、长度与类型三项判定，因此对应三个问题码；白名单外字段的判定对应 `W-FIELD-004`，与 V-11 同属字段类别但级别为警告。

## 5. 退出码

### 5.1 取值定义

| 退出码 | 含义 |
|---|---|
| `0` | 成功 |
| `1` | 通用失败或校验未通过 |
| `2` | 输入错误：参数、路径或名称不合法 |
| `3` | 索引或配置文件损坏，或版本不受支持 |
| `4` | 远端操作失败 |
| `5` | 文件系统操作失败，含回滚后仍失败 |
| `6` | 依赖未满足 |

### 5.2 派生规则

退出码由本次执行中出现的问题推导，推导顺序如下，命中即停：

1. 无任何错误级问题时，退出码为 `0`；
2. 存在问题码属于 `INPUT` 类别时，退出码为 `2`；
3. 存在问题码属于 `VER`、`INDEX` 或 `YAML` 类别，且**问题对象为索引或配置文件**时，退出码为 `3`；技能元文件（`source` 为 `meta`）的 `YAML` 类问题**不命中本步**，属技能级问题，按第 7 步归 `1`（2026-10-17 内核核查批次明确）；
4. 存在问题码属于 `SRC` 类别时，退出码为 `4`；
5. 存在问题码属于 `LOCK`、`IO` 或 `BAK` 类别时，退出码为 `5`；
6. 存在问题码属于 `DEP` 或 `RUN` 类别时，退出码为 `6`（`RUN` 是外部运行时的探测结论，语义上是依赖未满足的一种）；
7. 其余错误级问题，退出码为 `1`。

当某条指令另有专属的退出码规定时（见指令契约规范的指令总表与各指令小节），**专属规定优先于本节通用派生规则**，通用派生的档位对该指令不适用。`validate` 即适用此条：它的退出码口径由指令契约规范第 4.12 节单独规定，`DEP` 与 `VER` 档位对它不生效。

多条错误同时出现时，按上述顺序取最先命中的取值，并在 `findings` 中保留全部问题。

### 5.3 各类问题到退出码的映射

| 问题类别 | 退出码 |
|---|---|
| `INPUT` | `2` |
| `VER`、`INDEX`、`YAML`（作用于索引或配置文件） | `3` |
| `SRC` | `4` |
| `LOCK`、`IO`、`BAK` | `5` |
| `DEP`、`RUN` | `6` |
| `FIELD`、`ID`、`STATUS`、`TIME`、`HASH`、`PATH`、`CONFLICT`、`ENV` | `1` |
| 仅警告级问题，或 `ok` 为真 | `0` |

## 6. 输出通道与等价性

### 6.1 三种输出通道

| 通道 | 用途 | 说明 |
|---|---|---|
| 人类可读文本 | 终端直接使用 | 按问题分级着色，问题码与修复建议可见 |
| 机器可读结构 | 供脚本与宿主消费 | 即本规范定义的结果封装，完整无损 |
| 机器表格 | 供管道与快速解析 | 以制表符分隔的扁平结构，用于列表类输出 |

### 6.2 等价性要求

1. 三种通道承载的**信息集合必须一致**，不得出现某个通道缺失问题码或修复建议的情况；
2. 人类可读文本允许对字段做视觉分组与着色，但不得改变字段语义；
3. 机器可读结构是权威形态，其余两种通道均由其派生；
4. 界面宿主消费机器可读结构，不得解析人类可读文本。

### 6.3 日志的边界

结果封装是**面向调用方的返回**，日志是**面向排查的记录**，二者不得混用：

| 项目 | 结果封装 | 日志 |
|---|---|---|
| 去向 | 标准输出 | 工作区日志目录 |
| 内容 | 本次执行的结果与问题 | 执行过程与诊断信息 |
| 是否含明文凭据 | 不得包含 | 不得包含 |
| 是否稳定 | 契约固定 | 不承诺稳定 |

---

## 7. 契约稳定性

1. 结果封装的字段只增不改；新增字段必须为可选字段；
2. 已登记的问题码不得改变含义、级别或复用序号；
3. 退出码的取值不得改变含义；新增退出码需先修订本规范与需求文档；
4. 调用方必须以问题码而非说明文案作为判断依据。

---

## 8. 约束边界

1. 本规范不定义各指令的参数与行为，见指令契约规范；
2. 本规范不定义元数据字段的校验细节，见元数据规范；
3. 本规范不定义索引文件的结构，见索引格式规范；
4. 本规范不定义界面的呈现方式；
5. 问题码登记表中的条目必须与元数据规范的校验规则总表保持一一对应，新增校验规则时须同步登记问题码。
