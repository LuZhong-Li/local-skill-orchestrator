## 1. 文档概述

### 1.1 文档目的

本规范定义 skill-manager 管理元数据的**唯一契约**，用于约束下列三件事：

1. 每个 Skill 独立目录下的元文件应当包含哪些字段、字段取什么值、如何表达；
2. 工作区根目录下的全局索引应当保留哪些字段，以及各字段的权威来源；
3. 内核在安装、更新、校验三个环节应当如何判定字段是否合规、内容是否漂移。

本规范是内核校验能力的规则来源，也是外部工具与编辑器提示的依据。凡是与本规范冲突的字段写法，均视为不合规。

### 1.2 适用范围

| 属于本规范范围 | 不属于本规范范围 |
|---|---|
| `skill_meta.yaml` 的字段定义与校验规则 | `SKILL.md` 正文的内容与写作方式 |
| `skill_index.yaml` 的字段定义与校验规则 | 界面呈现、交互与视觉规范 |
| 标识、时间、哈希、YAML 四类基础规则 | 宿主 Agent 自身的配置格式 |
| 派生区字段的维护与篡改检测规则 | 校验器的实现方式与代码结构 |
| 规范版本与向后兼容策略 | 在线市场、多设备同步等二期能力的元数据 |
| 工作区内元文件与索引文件的位置约定 | 工作区备份目录、锁目录与日志目录的内容结构 |

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| **Skill** | 一个独占目录的能力单元，目录内含该 Skill 的元文件与附属资源 |
| **Skill ID** | Skill 的全局唯一标识，取值等于该 Skill 目录名，规则见 2.1 |
| **声明区字段** | 由用户或安装流程显式声明、允许编辑的字段。其权威来源为 `skill_meta.yaml` |
| **派生区字段** | 由系统自动计算生成、禁止用户手动修改的字段。其权威来源为内核在安装、更新、校验时写入的结果 |
| **工作区** | Skill 管理器的工作根目录，其布局由 AD-03 定义 |
| **元文件** | 每个 Skill 独立目录下的 `skill_meta.yaml`，承载该 Skill 的完整配置 |
| **全局索引** | 工作区根目录下的 `skill_index.yaml`，仅保留各 Skill 的最小引用字段 |
| **校验器** | 内核中负责比对元数据、配置与索引是否合规的只读能力，对应需求文档的校验需求 |
| **内容漂移** | 磁盘实际内容与已记录的内容指纹不一致的状态 |
| **引用摘要** | 索引中为满足列表展示而保留的字段级简写，其完整内容存于元文件 |

### 1.4 与上游文档的关系

1. 本规范落实架构决议 AD-01、AD-02、AD-03；
2. 本规范细化需求文档第 4 章的数据模型需求，覆盖 FR-01 至 FR-12 所依赖的全部元数据字段；
3. 本规范与需求文档第 4 章的差异集中登记在第 8 章，便于回写对齐。

关于路径命名的说明：本规范的仓库路径是 `docs/specification/`，属仓库文档目录；工作区内的 `./spec/` 是运行期目录，用于随工作区携带规范副本。二者同名部分容易混淆，因此特别区分：**仓库侧一律使用 `docs/specification/`，工作区侧一律使用 `./spec/`**。

## 2. 全局通用基础规则

### 2.1 Skill ID 命名规范

Skill ID 是 Skill 的全局唯一标识，同时作为该 Skill 所在目录的目录名。

| 规则项 | 要求 |
|---|---|
| 合法字符 | 仅允许小写字母、数字与短横线；允许 Unicode 字母，但在跨平台协作场景下建议只使用 ASCII |
| 大小写 | 必须全小写，禁止出现任何大写字母 |
| 长度上限 | 不超过 64 个字符 |
| 首尾限制 | 不得以短横线开头或结尾 |
| 连续限制 | 不得出现连续两个及以上的短横线 |
| 禁止字符 | 禁止空格、下划线、点号、斜杠、反斜杠、冒号、星号、问号、引号、竖线与各类控制字符 |
| 唯一性 | 在一个工作区内必须全局唯一。出现重复时以错误级问题报告，并要求用户处理，不得静默择一 |
| 目录一致性 | Skill ID 必须与所在目录名完全一致（大小写敏感） |
| 推荐风格 | 全小写、短横线分隔的通用英文单词组合，控制在 2 至 4 个词，例如 `code-review`、`doc-coauthoring` |

### 2.2 时间格式规范

时间字段用于记录 Skill 的生命周期节点，取值必须满足下列要求。

| 规则项 | 要求 |
|---|---|
| 格式 | 采用国际标准日期时间格式，形如 `2026-10-12T04:03:58Z` |
| 时区 | 统一使用协调世界时，以 `Z` 结尾 |
| 精度 | 精确到秒，不包含小数秒 |
| 禁止写法 | 禁止使用本地时区偏移形式，禁止使用仅含日期的写法，禁止使用中文或自然语言描述 |
| 校验要求 | 取值必须可被解析；`updated_at` 不得早于 `created_at` |

适用范围：`created_at`、`updated_at`，以及索引顶层的生成时间。

**用于文件系统位置时的转写**：时间戳作为目录名或文件名的一部分时，冒号在部分文件系统上非法，因此允许做**安全转写**：把 `:` 替换为 `-`，例如 `2026-10-14T16:00:58Z` 转写为 `2026-10-14T16-00-58Z`。转写只作用于文件系统位置，**字段取值不受影响**——记录在清单或元数据中的时间字段必须保持本节规定的原格式，不得写入转写后的形式。可比较性不因转写丢失：转写是单射，且分隔符位置固定。

**备份载体清单的时间戳唯一性**：备份载体清单里的 `timestamp` 是该份备份的**对外标识**——恢复指令按标识加时间戳寻址（指令契约 4.16），因此它必须唯一。同一 Skill 在同一秒内产出多份备份时，从第二份起把时间格式**按毫秒精度扩展**（形如 `2026-10-15T12:00:00.001Z`），逐个取值试探直到在候选集合内唯一；目录名同样按安全转写生成（`:` 替换为 `-`，其余字符原样保留），与清单取值一一对应。毫秒形式只出现在**备份载体清单**这一处；`created_at`、`updated_at`、`generated_at` 与 `validation.last_scan_at` 仍严格按本节规定的秒级精度书写，不得扩展。

### 2.3 Checksum 哈希规范

#### 算法与表示

| 规则项 | 要求 |
|---|---|
| 算法 | SHA-256 |
| 表示形式 | `sha256:` 前缀加 64 位小写十六进制，例如 `sha256:1f0482bf...` |
| 计算输入 | 原始字节流，不做任何归一化处理 |

#### 参与哈希的文件范围

| 范围 | 是否参与 | 说明 |
|---|---|---|
| Skill 目录内的普通文件 | 参与 | 包括 `SKILL.md`、脚本、引用文档与模板等附属资源 |
| `skill_meta.yaml` | **不参与** | 该文件是管理器元数据，不是 Skill 内容。若纳入范围，用户修改任一声明字段都会触发内容漂移误报 |
| 版本控制目录（如 `.git`） | 不参与 | 不属于 Skill 内容 |
| 备份文件与临时文件 | 不参与 | 由内核识别并排除 |
| 符号链接 | 不参与 | 不跟随链接，也不以链接目标内容参与计算；校验报告中另行提示存在链接项 |
| 空目录 | 不参与 | 目录结构本身不产生哈希贡献 |

#### 计算方式

1. 收集参与范围内的全部普通文件，取得其相对于 Skill 目录的相对路径；
2. 相对路径统一使用正斜杠分隔，不含前导的当前目录标记；
3. 按相对路径的字节序升序排列；
4. 逐文件以「相对路径、一个空字节、文件字节流」的顺序累加；
5. 对累加结果取 SHA-256，按上述表示形式输出。

#### 逐文件摘要

聚合指纹回答「内容是否变化」，**逐文件摘要**回答「哪个文件变了」。两者共存，各有用途。

| 规则项 | 要求 |
|---|---|
| 算法 | SHA-256，与聚合指纹同族 |
| 表示形式 | `sha256:` 前缀加 64 位小写十六进制 |
| 计算输入 | 单个文件的原始字节流，不拼接相对路径，不做任何归一化 |
| 参与范围 | 与聚合指纹的参与范围完全一致，共用同一套排除规则 |
| 键 | 该文件相对于 Skill 目录的路径，正斜杠分隔，取值集合与聚合指纹收集到的路径集合一致 |
| 存放位置 | 只存放在索引记录的派生区字段 `digests`；**元文件不承载该字段** |
| 更新时机 | 与聚合指纹一致：由内核在登记、安装、更新与恢复时写入 |

两级取值互不派生：聚合指纹把路径与内容一并累加，无法由逐文件摘要还原；逐文件摘要也不由聚合指纹拆分得到。比对规则见 5.4 节。

#### 用途

| 用途 | 说明 |
|---|---|
| 安装 | 安装完成后写入该 Skill 的内容指纹 |
| 校验 | 与磁盘实际内容比对，判断是否发生内容漂移 |
| 更新 | 更新前比对，识别用户对 Skill 内容的本地修改 |
| 备份与导入 | 校验备份内容的完整性与一致性 |

#### 校验失败判定

| 情形 | 判定 |
|---|---|
| 指纹与磁盘内容一致 | 通过 |
| 指纹与磁盘内容不一致 | 判定为**内容漂移**，属于警告级问题，不得阻断常规使用 |
| 指纹缺失或格式不合规 | 判定为**错误级**问题，需要重新登记或重新安装 |
| 参与范围内的文件全部缺失 | 判定为**错误级**问题，同时触发记录失效的判定 |

内容漂移之所以定为警告级，是因为用户对 Skill 内容的本地修改是合理场景，不具备阻断性；而指纹缺失意味着管理器无法判断内容完整性，属于契约缺失，因此定为错误级。

### 2.4 YAML 文件基础约束

下列约束同时适用于 `skill_meta.yaml` 与 `skill_index.yaml`。

| 约束项 | 要求 |
|---|---|
| 编码 | UTF-8，不携带字节顺序标记 |
| 换行 | 统一使用换行符 `LF` |
| 缩进 | 统一使用 2 个空格，禁止使用制表符 |
| 文档流 | 单文档流，禁止在同一文件内使用多个文档分隔符串联多份文档 |
| 顶层结构 | 顶层必须是映射结构，不得为序列或标量 |
| 锚点与别名 | 禁止使用锚点、别名与自定义标签 |
| 重复键 | 同一层级内禁止出现重复键 |
| 注释 | 允许使用 `#` 注释，注释不得改变字段结构 |
| 字符串引号 | 含特殊字符、含前导零或以数字形态呈现的字符串必须加引号，例如版本号必须写作带引号的 `"1.2.0"`，避免被解析为数值 |
| 枚举取值 | 一律使用小写英文单词 |
| 空值 | 可选字段缺失时直接省略该键，不建议显式书写空值 |

## 3. `skill_meta.yaml`（单 Skill 元文件）

### 3.1 文件定位

| 项目 | 说明 |
|---|---|
| 位置 | 每个 Skill 的独占目录内，与 `SKILL.md` 同级 |
| 数量 | 一个 Skill 目录有且仅有一份 |
| 权限 | 声明区字段允许用户编辑；派生区字段只能由内核写入 |
| 权威性 | 该 Skill 的完整配置以本文件为权威来源 |

### 3.2 声明区字段

| 字段名 | 数据类型 | 必填/可选 | 归属分区 | 描述 | 校验规则 |
|---|---|---|---|---|---|
| `id` | 字符串 | 必填 | 声明区 | Skill 的唯一标识 | 满足 2.1 全部规则；必须与所在目录名完全一致；在工作区内唯一 |
| `name` | 字符串 | 必填 | 声明区 | 展示名称 | 非空字符串；不含首尾空白；长度不超过 64 个字符 |
| `version` | 字符串 | 可选 | 声明区 | Skill 版本号 | 语义化版本三段式；必须加引号书写；缺失时不参与更新比较 |
| `description` | 字符串 | 可选 | 声明区 | 功能与适用场景说明 | 长度不超过 1024 个字符；不得为空字符串 |
| `author` | 字符串 | 可选 | 声明区 | 作者或维护者标识 | 非空字符串；推荐使用可追溯的账号或名称形式 |
| `license` | 字符串 | 可选 | 声明区 | 许可协议标识 | 推荐使用通用协议标识写法，例如 `MIT`、`Apache-2.0` |
| `status` | 字符串枚举 | 必填 | 声明区 | 启用状态 | 仅允许 `enabled` 或 `disabled` 两个取值，见 5.5 |
| `path` | 字符串 | 必填 | 声明区 | 该 Skill 目录相对于工作区根目录的路径 | 必须位于 `./skills/` 之下；使用正斜杠分隔；禁止绝对路径；禁止包含上级目录跳转标记 |
| `trigger_keywords` | 字符串数组 | 可选 | 声明区 | 触发关键词列表 | 每项为非空字符串且不超过 32 个字符；列表内不得重复；建议不超过 10 项 |
| `dependencies` | 映射 | 可选 | 声明区 | 依赖声明 | 结构见 3.3；被依赖对象必须存在或给出可执行的补齐建议 |
| `source` | 映射 | 必填 | 声明区 | 来源信息 | 结构见 3.4；来源类型为本地目录时地址与引用标识可省略，其余类型均必填 |
| `targets` | 映射数组 | 必填 | 声明区 | 落位目标列表 | 结构见 3.5；至少一项；目标标识不得重复 |

### 3.3 `dependencies` 结构

| 子字段 | 数据类型 | 必填/可选 | 描述 | 校验规则 |
|---|---|---|---|---|
| `skills` | 字符串数组 | 可选 | 依赖的其他 Skill 及其版本约束 | 每项形如「Skill ID 加版本约束」；被依赖项必须存在；版本必须满足约束 |
| `runtime` | 映射 | 可选 | 依赖的外部运行时及其版本约束 | 键为运行时名称（可执行文件名，例如 `node`、`python`、`git`）；值为版本约束字符串，语法为语义化版本的范围表达式（`>=1.2.3`、`^1.2.3`、`~1.2.3`、`1.2.x` 等）；非空且必须可解析为合法范围，否则报无效约束；运行时的探测结果见 5.3 节 |

**运行时依赖的边界**：`runtime` 声明的是**执行环境**的要求，不是 Skill 自身的内容。因此：

1. 探测结果（运行时是否可用、实际版本是多少）属于**环境相关数据**，**不写入索引、不写入运行期结论**——索引保持环境无关，同一份索引在不同机器上读取时不应因环境差异而含义不同；
2. 运行时是否满足由依赖检查动作（`deps`）**实时探测并呈现**，不作为该 Skill 的校验结论；详见 5.3 节的判定边界。

### 3.4 `source` 结构

| 子字段 | 数据类型 | 必填/可选 | 描述 | 校验规则 |
|---|---|---|---|---|
| `type` | 字符串枚举 | 必填 | 来源类型 | 仅允许 `local`、`git`、`archive`、`unknown` 四个取值 |
| `location` | 字符串 | 条件必填 | **本地形式**的来源位置：本地仓库路径或归档文件路径 | 来源类型为 `git` 或 `archive` 且来源就在本机时给出；给出后不再要求 `url` 与 `ref` |
| `url` | 字符串 | 条件必填 | **远端形式**的来源地址 | 来源类型非 `local` 且非 `unknown`、且未给出 `location` 时必填 |
| `ref` | 字符串 | 条件必填 | 引用标识，记录分支、标签或提交标识 | 与 `url` 同时必填；给出 `location` 时可省略，省略时按默认分支读取 |
| `subpath` | 字符串 | 可选 | 来源仓库内的具体子目录 | 使用正斜杠分隔；不得包含上级目录跳转标记 |

来源分本地与远端两种形式：**本地形式**用 `location` 指向本机的仓库目录或归档文件，**远端形式**用 `url` 与 `ref` 指向可远程访问的地址。刷新指令按来源声明决定是否重新获取内容——本地形式与归档形式会重新读取来源并替换中心库原件，远端形式依赖远端拉取能力。来源标识只允许分支名、标签或提交标识的字符集，且不得以短横线开头，以免被当作命令选项。

来源类型为 `unknown` 时，`url` 与 `ref` 均省略，该 Skill 在界面上以来源未知状态呈现，且更新能力不可用。

### 3.5 `targets` 结构

`targets` 为映射数组，每项描述该 Skill 在一个目标位置上的一次落位。

**目标落位根约定**：受控副本的位置由约定推导，不由元文件自由指定——**落位根**为工作区根目录下的 `.<目标标识>/skills`，该目标下的副本目录为 `<落位根>/<Skill 标识>`。例如标识为 `code-review` 的 Skill 在 `claude` 目标下的副本目录是 `./.claude/skills/code-review`。约定化的理由是副本定位必须**不依赖中心库原件是否存在**：原件缺失时，卸载仍要能按约定找到并回收副本。因此元文件中的 `path` 必须与约定一致，不一致按字段取值问题拒绝登记。

| 子字段 | 数据类型 | 必填/可选 | 描述 | 校验规则 |
|---|---|---|---|---|
| `target` | 字符串 | 必填 | 目标位置的标识名 | 非空字符串；同一 Skill 内不得重复 |
| `scope` | 字符串枚举 | 必填 | 作用域 | 仅允许 `global` 或 `project` |
| `path` | 字符串 | 必填 | 该 Skill 在该目标下的副本目录 | 必须**等于**目标落位根约定给出的路径；禁止绝对路径；使用正斜杠分隔 |
| `mode` | 字符串枚举 | 必填 | 落位方式 | 仅允许 `copy` 或 `link`；一期默认使用 `copy` |
| `enabled` | 布尔 | 必填 | 该目标下是否生效 | 取值为真或假；与同级的 `status` 共同决定实际可见性 |
| `file_map` | 映射 | 可选 | 逐文件的来源与落位对应关系 | 键为原件内的相对路径，值为该文件在副本目录下的相对路径；**缺省表示整目录复制**，提供时必须逐条校验：源文件在原件中必须存在、目标不得越出副本目录、同一目标不得被多个条目占用 |

**`file_map` 的两种形态**：

| 形态 | 行为 |
|---|---|
| 缺省 | 整目录复制：把中心库原件的全部内容复制到副本目录，保持相对路径不变 |
| 提供 | 逐文件映射：只落位映射表列出的文件，源为原件内的相对路径，目标为副本目录下的相对路径；未列出的文件不落位 |

逐文件映射使得同一 Skill 可以只向某个目标分发其中一部分内容，也让「哪些文件属于该 Skill」在卸载时可精确回收——回收范围就是副本目录本身，与映射内容无关。

禁用标记说明：落位在目标位置的内容是内核维护的受控副本。一期统一采用**副本内技能元数据文件改名**的方式表达禁用——把副本内的技能元数据文件重命名为带禁用后缀的名称，宿主按既有发现规则不再识别为可用；启用时改回原名。该规则在一期固定，**不在元文件中逐目标配置**，因此本结构不设禁用标记子字段。该机制只作用于副本，中心库原件与用户源文件一律不改动，也不移动、重命名或删除任何目录。

### 3.6 派生区字段

| 字段名 | 数据类型 | 必填/可选 | 归属分区 | 描述 | 校验规则 |
|---|---|---|---|---|---|
| `created_at` | 字符串 | 必填 | 派生区 | 首次登记时间 | 满足 2.2；由内核在首次登记或安装时写入 |
| `updated_at` | 字符串 | 必填 | 派生区 | 最近一次变更时间 | 满足 2.2；由内核在安装、更新、校验时更新；不得早于 `created_at` |
| `checksum` | 字符串 | 必填 | 派生区 | Skill 内容的一致性与完整性校验值 | 满足 2.3；由内核计算并写入 |

**派生区字段的必填性分两处，不可混同：**

| 位置 | 必填性 | 理由 |
|---|---|---|
| `skill_meta.yaml` | **可选**。缺失表示待内核回填，不构成不合格 | 派生区是内核产物，用户手工编写的元文件天然不含这些字段；若按必填判定，每个新 Skill 一入索引即为校验不通过 |
| `skill_index.yaml` | **必填** | 索引同样是内核产物，写入时必然已具备这些取值 |

因此在元文件上，只有「字段存在但格式不合规」才报告问题；缺失时由内核在登记、安装与扫描时回填。

| 字段名 | 数据类型 | 必填/可选 | 归属分区 | 描述 | 校验规则 |
|---|---|---|---|---|---|

#### 派生区字段

| 字段名 | 数据类型 | 必填/可选 | 归属分区 | 描述 | 校验规则 |
|---|---|---|---|---|---|
| `created_at` | 字符串 | 必填 | 派生区 | 首次登记时间 | 满足 2.2；与元文件取值一致 |
| `updated_at` | 字符串 | 必填 | 派生区 | 最近一次变更时间 | 满足 2.2；与元文件取值一致 |
| `checksum` | 字符串 | 必填 | 派生区 | Skill 内容指纹 | 满足 2.3；与元文件取值一致 |
| `digests` | 映射 | 可选 | 派生区 | 逐文件内容摘要：键为该文件相对 Skill 目录的路径，值为该文件的内容摘要 | 键的集合与聚合指纹的参与范围一致；值为 2.3 规定的摘要表示形式；由内核在登记、安装、更新与恢复时写入；缺失表示待内核回填（例如本字段引入之前生成的旧索引），不属于不合格 |

说明：索引中的派生区字段**除 `digests` 外**必填，与元文件中的可选性不同——索引由内核写入，必然已具备这些取值；元文件由用户编写，缺失时由内核回填。`digests` 是本字段引入后才有的派生数据，旧索引里没有它属于正常状态，因此按可选处理：缺失表示待内核回填，由下一次登记与刷新补齐；补齐之前内容一致性校验退化为聚合级报告（见 5.4 节），不产生误报。对照说明见 3.6 节。

#### 运行期结论字段

该区块由扫描动作计算生成，**不是元文件的投影**，因此不参与投影一致性判定；其取值随每次扫描重新计算。

| 字段名 | 数据类型 | 必填/可选 | 归属分区 | 描述 | 校验规则 |
|---|---|---|---|---|---|
| `validation` | 映射 | 必填 | 运行期结论 | 该 Skill 最近一次校验的结论 | 结构见下表；缺失时按未校验处理并给出警告 |
| `validation.status` | 字符串枚举 | 必填 | 运行期结论 | 校验结论 | 仅允许 `ok` 或 `invalid` |
| `validation.errors` | 数组 | 必填 | 运行期结论 | 本次校验的问题码与失败详情 | 无问题时为空数组；有结论为 `invalid` 时不得为空 |
| `validation.last_scan_at` | 字符串 | 可选 | 运行期结论 | 最近一次扫描写入该结论的时间 | 满足 2.2 的时间格式；**仅由扫描动作写入**，其余指令一律不得刷新。缺失表示该记录尚未经过扫描，例如刚由安装登记、尚未扫描的记录 |

约束：

1. 该区块**只由扫描动作写入**，其余全部指令一律不得改动；
2. 校验动作对该区块保持只读，不得改写；
3. 该区块不得与 `status` 混用：`validation.status` 为 `invalid` 表示校验不通过，与用户是否主动启停该 Skill 无关。
4. **不合格的 Skill 同样入索引**：`validation.status` 为 `invalid` 的记录是一条正常存在的索引记录，既不是悬空记录，也不得被静默丢弃；其问题明细写入 `validation.errors`；
5. **自动复检**：同一 Skill 重复扫描时更新既有记录，不新增重复条目；问题修复后再次扫描，结论自动转为 `ok`，无需人工干预；
6. **可用性判定**：仅当 `validation.status` 为 `ok` 时该记录进入可用集合。结论为 `invalid` 的记录可被查看与卸载，但其启用操作必须被拒绝，拒绝原因与该 Skill 被用户禁用须在问题码上区分。

### 4.5 索引不存储的内容

下列内容一律不写入索引，只存于元文件：

1. 来源地址、引用标识与来源子路径的完整取值；
2. 落位路径与落位方式的完整取值；
3. 逐文件的来源与落位对应关系；
4. 依赖的完整版本约束；
5. Skill 目录内的文件清单与文件内容。

## 5. 统一校验规则总表

### 5.1 规则分级

全部校验结论分为两级，级联到界面呈现与退出码：

| 级别 | 含义 | 后续行为 |
|---|---|---|
| 错误 | 契约被破坏，管理器无法保证行为正确 | 阻断对应操作；校验以非零状态结束 |
| 警告 | 不阻断使用，但需要用户关注 | 允许继续；在校验报告中归类为警告项 |

### 5.2 Skill ID 唯一性校验

| 项目 | 内容 |
|---|---|
| 校验对象 | 全局索引内的 `id` 字段，以及 `./skills/` 下的目录名 |
| 触发时机 | 登记、安装、导入、校验 |
| 判定规则 | 一个 Skill 目录恰好对应一条记录（**物理唯一**）；`id` 与所在目录名必须完全一致（大小写敏感，不一致报 V-03）；不同目录的 `id` 不得重复（重复报 V-02，逐条列出冲突双方）；记录声明的物理位置必须可达；`id` 必须满足 2.1 的全部字符与长度规则 |
| 级别 | 全部为错误级。重复出现时不得静默择一，必须逐条列出冲突的双方 |
| 输出要求 | 指明重复的 `id`、涉及的记录位置或目录路径，并给出可执行的处置建议；**逻辑错误只报告、不得改变记录的物理归属**（扫描不得因 `id` 异常而增删记录） |

### 5.3 `dependencies` 校验

| 项目 | 内容 |
|---|---|
| 校验对象 | 元文件中的 `dependencies.skills` 与 `dependencies.runtime` |
| 触发时机 | 安装、更新、校验、卸载前的依赖影响面分析；运行时的实时探测由依赖检查动作承担 |
| 判定规则 | 被依赖的 Skill 必须存在于索引中**且其运行期结论为校验通过**；被依赖对象不在索引中、或其运行期结论为校验不通过时，依赖方一律判定为依赖未满足；依赖关系不得成环 |
| 判定边界 | 本项只判定**Skill 之间的依赖**——它决定该 Skill 自身的校验结论。`dependencies.runtime` 是环境要求：运行时的可用性与实际版本由依赖检查动作**实时探测并呈现**，**不参与**该 Skill 的校验结论，也不写入索引与运行期结论（理由见 3.3 节的运行时依赖边界）。因此「运行时缺失」不会把一条内容完好的 Skill 判为校验不通过，也不会污染记录结论 |
| 级别 | Skill 依赖缺失、依赖成环为错误级；运行时的探测结论按问题码分级（见结果规范的运行时类），由依赖检查动作呈现 |
| 输出要求 | 逐条列出缺失或冲突的对象名、当前版本与要求版本，并给出可直接执行的补齐建议；运行时的条目给出运行时名称、期望约束原文、探测到的版本与结论 |
| 约束 | 只检查与报告，**不自动安装任何依赖** |

**依赖环的报告形态（2026-10-17 内核核查批次）**

1. 环在**全量依赖图**上检测（以全部 `dependencies.skills` 建图，**不受运行期可用性影响**）；自环与长度 ≥ 2 的环都算环，环成员的结论不随扫描的迭代轮次变化；
2. 环上**每个** Skill 各带一条 `E-DEP-003`（`target` 为自身标识）；环成员**不叠加** `E-VALIDATION-002`（根因只归一次环）；
3. 环**外**依赖环上 Skill 的记录（直接或传递）带 `E-VALIDATION-002`；环成员若同时声明了不存在的依赖，仍报 `E-DEP-001`；
4. `deps` 指令的环列表与上述结论一致（同一组环、同一批成员）；
5. 异常记录（`id` 与目录名不一致、跨目录 `id` 重复）**不参与合法依赖解析**，按不可用进入传播。

### 5.4 `checksum` 完整性校验

| 项目 | 内容 |
|---|---|
| 校验对象 | 元文件与索引中的 `checksum`，以及磁盘上该 Skill 目录的实际内容 |
| 触发时机 | 校验、更新前、导出、导入 |
| 判定规则 | 按 2.3 的算法与文件范围重新计算，与记录值逐字符比对 |
| 级别 | 不一致判定为内容漂移，属警告级；`checksum` 缺失或格式不合规则为错误级；参与范围内的文件全部缺失为错误级，并同时触发记录失效判定 |
| 输出要求 | 指出发生漂移的 Skill、记录的指纹与重算的指纹；**并逐文件列出发生变化的文件相对路径与其新旧摘要**——判据为索引派生区的 `digests` 与磁盘重算的逐文件摘要比对，覆盖「内容变化」「新增」「删除」三种情形，每条给出文件相对路径与两侧摘要取值。索引内缺少 `digests`（旧索引尚未回填）时退化为聚合级报告：只给记录指纹与重算指纹，并提示重新扫描以补齐逐文件基准，**不猜测具体文件、不误报** |
| 备注 | 元文件自身的变更不参与本项校验，避免用户调整声明字段即触发误报 |

### 5.5 派生区字段篡改检测

| 项目 | 内容 |
|---|---|
| 校验对象 | 元文件与索引中的 `created_at`、`updated_at`、`checksum`，以及索引顶层的 `generated_at` |
| 触发时机 | 校验 |
| 判定规则 | 派生区字段只允许由内核在安装、更新、校验三个动作中写入。若检测到取值与内核可推导的结果不一致，或检测到字段被用户直接改写，即判定为篡改 |
| 级别 | 警告级。派生区字段的异常不阻断使用，但必须提示 |
| 输出要求 | 逐条列出被改动的字段名、记录值与内核推导值，并提示这些字段将由内核在下次安装、更新或校验时自动覆盖 |
| 强制约束 | 用户手动修改派生区字段属于违规操作；内核不得以用户写入的派生区取值作为任何判定或配置的输入 |

说明：本项的比对集合是**元文件与索引共同承载**的三个派生字段（`created_at`、`updated_at`、`checksum`）。逐文件摘要 `digests` 只存在于索引、元文件不承载该字段，因此不参与本项比对；索引中的 `digests` 与磁盘实况的比对归 5.4 节的内容一致性校验。

### 5.6 `status` 枚举校验

| 项目 | 内容 |
|---|---|
| 校验对象 | 元文件与索引中的 `status` |
| 触发时机 | 登记、安装、启用、禁用、校验 |
| 判定规则 | 仅允许 `enabled` 与 `disabled` 两个取值，区分大小写，禁止空值、布尔值与其他同义写法 |
| 级别 | 取值不在枚举范围内为错误级 |
| 输出要求 | 指明字段位置、实际取值与允许取值 |
| 一致性要求 | 索引中的 `status` 是启用状态的**唯一事实源**，不参与投影一致性判定：元文件中的 `status` 只表达作者声明的初始状态，索引中的 `status` 是运行期事实，安装动作决定登记取值（见 4.7 行为 7 的对应指令契约与 D-08）。二者取值不一致时不产生告警，也不得据此改写元文件 |
| 术语对照 | `enabled` 对应启用，`disabled` 对应禁用。中英对照关系以需求文档 4.2 节为单一出处，本规范不另行定义中文表述 |
| 与校验结论的关系 | 本枚举只表达用户是否主动启停该 Skill，**不承载校验结论**。校验不通过由索引中的运行期结论区块单独表达，二者不得混用 |

### 5.7 跨文件投影一致性校验

| 项目 | 内容 |
|---|---|
| 校验对象 | 索引记录与该 Skill 元文件中的同名字段 |
| 触发时机 | 校验 |
| 判定规则 | 比对集合限定为声明区中**除 `status` 与 `targets.enabled` 之外**的字段：`name`、`version`、`description`、`author`、`license`、`path`、`trigger_keywords`、`source_type`、`created_at`、`updated_at`、`checksum` 在索引与元文件之间必须一致；`targets` 摘要必须与元文件中的对应项在 `target` 与 `scope` 两个子字段上一致 |
| 排除项说明 | `status` 被排除，因为索引中的该字段是启用状态的唯一事实源（见 5.6），安装动作会按 4.7 行为 7 与 D-08 决定登记取值，元文件取值不参与判定；`targets.enabled` 被排除，因为它是各目标位置的运行期可见性，由启用、禁用与仅落库安装等动作决定，元文件取值只表达作者声明的初始意图。二者都属于「运行期事实」而非「元文件投影」，判为投影不一致会把合法操作误报为问题 |
| 级别 | 不一致为警告级，并提示以元文件为准重新生成索引投影 |
| 输出要求 | 逐字段列出两侧取值与差异字段名 |

## 8. 约束边界

### 8.1 本规范不定义的内容

1. 不定义 `SKILL.md` 正文的写作方式与内容质量；
2. 不定义界面呈现、交互流程与视觉规范；
3. 不定义校验器、索引写入器等任何实现结构；
4. 不定义宿主 Agent 的目录约定与配置格式；
5. 不定义在线市场、多设备同步、自动更新等二期能力的元数据；
6. 不定义备份载体自身的文件结构，仅约束其中的元数据字段。
7. 不定义工作区内备份目录、锁目录与日志目录的内容结构，三者的归属与约束见需求文档 4.3 节与 4.4 节。

### 8.2 派生区写入的强制约束

以下三条为**硬性约束**，任何实现与使用方式都不得突破：

1. **写入主体唯一**：派生区字段只能由 skill-manager 内核在安装、更新、校验三个动作中自动写入；
2. **用户改动属违规**：用户手动修改派生区字段属于违规操作。内核在校验阶段必须检测并告警，告警内容需指明被改动的字段名；
3. **不得作为输入**：派生区字段的取值不得作为任何配置、判定或业务规则的输入来源，仅用于一致性判断与结果展示。

### 8.3 与需求文档的差异登记

下列差异来自架构决议对需求文档的收窄或细化，需在后续批次回写需求文档第 4 章，以保证两份文档口径一致。

| D-01 | 索引是否存储来源与落位明细 | 需求文档 4.2 节将「来源信息块」与「落位目标列表」列为索引内的必填字段 | 索引只保留来源类型摘要与落位目标摘要；来源地址与引用标识、落位路径与落位方式、逐文件映射均移入元文件 | AD-01 |
| D-02 | 索引中两个引用摘要字段 | 需求文档的声明区字段清单未包含来源类型摘要 | 为满足列表视图展示来源类型与部署目标，索引保留 `source_type` 与 `targets` 两个摘要字段，并明确其为引用投影 | 需求文档 FR-03 |
