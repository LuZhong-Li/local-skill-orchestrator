## 1. 文档概述

### 1.1 目的

本规范逐条定义 skill-manager 对外提供的全部指令契约，包括语法、参数、选项、前置条件、执行行为、输出载荷与退出码。

界面宿主的每一次操作都对应本规范中的一条指令，界面不得新增指令，也不得组合出契约之外的语义。

### 1.2 适用范围

| 属于本规范范围 | 不属于本规范范围 |
|---|---|
| 指令名称、语法与参数 | 结果封装与退出码的定义，见结果封装与退出码规范 |
| 每条指令的行为与前置条件 | 元数据字段与索引结构，见元数据规范与索引格式规范 |
| 每条指令的输出载荷 | 界面呈现与交互细节 |
| 通用选项与通用行为 | 内核模块的内部实现 |

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| **指令** | 一次调用所执行的动作，例如安装或禁用 |
| **位置参数** | 直接跟在指令名之后的目标对象，例如 Skill 标识或来源 |
| **选项** | 以短横线开头的具名参数，用于修饰指令行为 |
| **目标位置** | 一个具体的落位目的地，由目标标识与作用域共同确定 |
| **落位** | 把中心库中的 Skill 内容部署到某个目标位置的动作 |
| **预演** | 只生成并返回变更清单、不执行写入的执行方式 |
| **轻确认** | 在操作面板内以行内方式确认，再次触发同一动作即生效 |

## 2. 通用约定

### 2.1 调用形式

指令的统一调用形式为：管理器名、指令名、位置参数、选项。指令名使用完整英文单词，不使用缩写；多条指令的层级最多两层，即「动作分组加动作」。

### 2.2 通用选项

下列选项对所有指令通用。

| 选项 | 形式 | 含义 |
|---|---|---|
| 机器可读输出 | `--json` | 输出结果封装结构，供脚本与宿主消费 |
| 机器表格 | `--machine` | 输出以制表符分隔的扁平结构，用于列表类结果 |
| 预演 | `--dry-run` | 只返回变更清单，不执行写入 |
| 跳过确认 | `--yes` | 跳过交互确认，适用于自动化调用 |
| 目标 | `--target <目标标识>` | 指定目标位置；省略时使用配置区的默认目标 |
| 作用域 | `--scope <global 或 project>` | 指定目标的作用域 |
| 工作区 | `--workspace <路径>` | 指定工作区根目录，覆盖环境变量与默认目录 |
| 详细日志 | `--verbose` | 输出诊断信息到日志，不改变结果封装 |
| 关闭着色 | `--no-color` | 关闭人类可读输出的颜色 |
| 帮助 | `--help` | 输出该指令的用法、参数与示例 |
| 版本 | `--version` | 输出版本信息，不执行任何操作 |

除 `--help` 与 `--version` 外，其余选项均不改变指令的语义，只改变执行方式或输出形态。

**工作区根目录的优先级链**：`--workspace` 选项 高于 环境变量 `SKILL_MANAGER_HOME` 高于 默认目录。默认目录为用户主目录下的 `.skill-manager`。三者都不提供时使用默认目录；链上任一环节给出取值即覆盖其后环节。

**宿主分发的入口**：`--host <宿主>` 是宿主适配层的显式入口，仅 `install`、`enable`、`disable`、`update` 四条指令接受。取值来自宿主注册表（宿主标识，含按路径类分条的取值，如 `cursor` 与 `cursor-rules`），取值域由注册表决定，未登记的取值判为参数类问题并列出可用取值。

`--host` 与 `--target` **正交**：`--target` 决定工作区内的目标位置（沿用可推导布局 `.<目标标识>/skills/<Skill 标识>`，语义与一期一致、不作变更），`--host` 决定分发到哪个宿主的**真实根**（位于工作区之外，如 `~/.claude/skills`）。两者可并用，各自生效、互不影响。宿主真实根按「默认路径 + 配置覆盖」解析，配置键见 4.3 节。

写工作区之外的路径属高影响操作：沿用确认机制（非终端环境必须给出 `--yes`，否则拒绝执行并返回参数类错误），并支持 `--dry-run` 预览将写入的工作区外路径。

**重复给出的处理**：同一命令中重复出现同一选项按**参数类错误**拒绝（`E-INPUT-002`），**不静默取最后值**——该口径对布尔选项与取值选项一致，防止误写的参数被悄悄丢弃。设计上可重复的取值选项在各自语法中标记为 `...`（当前仅 `scan` 的 `--root`），重复给出时按数组聚合。选项的可重复性在解析器的登记表中显式声明，默认单值。

### 2.3 通用行为

| 行为 | 要求 |
|---|---|
| 幂等 | 重复执行同一指令不得产生重复结果或错误 |
| 失败原子性 | 指令失败后，磁盘与索引必须与执行前一致 |
| 预演不落盘 | 预演必须真实反映将要发生的变更，但不得写入任何文件 |
| 结果恒定 | 同一环境与同一参数下，结果封装的结构固定 |
| 日志边界 | 诊断信息写入工作区日志目录，不混入结果封装 |

### 2.4 确认强度

| 级别 | 适用指令 | 要求 |
|---|---|---|
| 无需确认 | 启用、禁用、查看详情、复制日志、导出备份 | 直接执行 |
| 轻确认 | 导入备份、安装 | 行内二次触发生效 |
| 强制二次确认 | 卸载 | 独立确认，须逐条列出影响范围与文件数量，默认聚焦取消 |

一期安装不覆盖既有记录（重复标识一律拒绝），因此不存在「覆盖既有 Skill 的安装」这一情形；轻确认对**全部安装**生效。

**强制确认的含义**：强制二次确认指**独立的多行确认块 + 默认取消**，不是字面上的两次问答。确认块必须逐条列出影响范围与文件数量；带 `--hard` 时在确认块中单独指明中心库原件将被永久删除，并另行标注本次为强制确认级别。

**非终端环境**：无 TTY 时执行需要确认的操作，必须显式提供跳过确认选项（`--yes`）；否则拒绝执行并返回参数类错误（`E-INPUT-001`），提示调用方显式给出 `--yes` 或改用 `--dry-run` 预览。该行为保证脚本与进程间调用不会因等待交互输入而挂起。

传入跳过确认选项时，轻确认与强制二次确认均被跳过，但**影响范围的说明仍必须出现在结果封装中**。

### 2.5 取值域

| 概念 | 允许取值 |
|---|---|
| 启用状态 | 已启用、已禁用 |
| 来源类型 | 本地目录、Git 仓库、归档文件、来源未知 |
| 作用域 | 全局级、项目级 |
| 落位方式 | 副本、链接。一期实际仅使用副本 |
| 冲突策略 | 保留旧值、采用备份值、两者并存 |

## 3. 指令总表

| 序 | 指令名 | 作用 | 是否写操作 | 需确认级别 | 退出码范围 |
|---|---|---|---|---|---|
| 1 | `init` | 建立工作区与索引 | 是 | 无需 | 0 至 5 |
| 2 | `config get` | 读取当前配置 | 否 | 无需 | 0 至 3 |
| 3 | `config set` | 修改配置项 | 是 | 无需 | 0 至 5 |
| 4 | `scan` | 发现并登记 Skill | 是 | 无需 | 0 至 5 |
| 5 | `list` | 列出已管理 Skill | 否 | 无需 | 0 至 3 |
| 6 | `inspect` | 查看单个 Skill | 否 | 无需 | 0 至 3 |
| 7 | `install` | 从来源安装并登记 | 是 | 轻确认 | 0 至 6 |
| 8 | `uninstall` | 移除并精确回收文件 | 是 | 强制二次确认 | 0 至 5 |
| 9 | `enable` | 使 Skill 在目标位置生效 | 是 | 无需 | 0 至 6 |
| 10 | `disable` | 使 Skill 在目标位置不生效 | 是 | 无需 | 0 至 5 |
| 11 | `update` | 从来源更新到较新版本 | 是 | 轻确认 | 0 至 6 |
| 12 | `validate` | 校验元数据、配置与索引 | 否 | 无需 | 0 至 3 |
| 13 | `deps` | 检查依赖满足情况 | 否 | 无需 | 0 至 6 |
| 14 | `export` | 导出元信息与状态 | 是 | 无需 | 0 至 5 |
| 15 | `import` | 从备份恢复 | 是 | 轻确认 | 0 至 6 |
| 16 | `restore` | 从备份载体恢复内容 | 是 | 常规确认 | 0 至 5 |

指令名是契约的一部分：界面宿主与命令行必须使用同一套指令名，不做任何映射或改写。别名不属于契约，使用别名不得改变行为。

个别指令的退出码口径另有专属规定时，**专属规定优先于结果封装与退出码规范第 5.2 节的通用派生规则**；通用派生中的 `DEP`、`VER`、`INDEX` 档位对该指令不适用。目前适用此条的指令为第 12 条 `validate`，其口径见第 4.12 节。

退出码范围随机制走：当某条指令的某个分支必然产生更高档位的问题码时，范围列应反映该真实可达值，而不是反过来为迁就范围改问题码。第 9 条 `enable` 的范围因此为 0 至 6——它的依赖类分支（`E-DEP-001` 与 `E-VALIDATION-002`）可达退出码 `6`，该分支仅在索引运行期结论过期时触发。

## 4. 逐条指令契约

### 4.1 `init`

**用途**：在工作区建立索引、配置区与标准目录结构。

**语法**：`skill-manager init [--scope <global|project>] [--workspace <路径>]`

**前置条件**：目标位置尚未存在索引文件。

**工作区选择**：按第 2.2 节的优先级链确定工作区根目录，即 `--workspace` 高于环境变量 `SKILL_MANAGER_HOME` 高于默认目录。

**行为**：

1. 建立索引文件，写入当前格式版本与工具版本；
2. 写入配置区的初始内容，包括 Skill 根目录列表与默认目标；
3. 建立工作区的标准目录；
4. 若索引已存在则失败，不覆盖既有工作区。

**输出载荷**：工作区路径、索引路径、创建时间。

**预演与确认**：无需确认；支持预演。

### 4.2 `config get`

**用途**：读取当前配置区的全部内容。

**语法**：`skill-manager config get`

**前置条件**：工作区已初始化。

**行为**：读取索引文件配置区并原样返回，不做任何推导或补默认值。

**输出载荷**：Skill 根目录列表、默认目标、默认落位方式。

**预演与确认**：只读指令，不需要确认，不支持预演。

### 4.3 `config set`

**用途**：修改单个配置项。

**语法**：`skill-manager config set <配置键> <配置值>`

**可修改配置项**：Skill 根目录列表、默认目标、默认落位方式，以及宿主真实根的两项配置键。

**宿主真实根的配置键**：`host.<宿主标识>.root`（技能根）与 `host.<宿主标识>.rules_root`（规则路径根）。宿主标识必须是宿主注册表中已登记的标识；取值非空，作为宿主落位根覆盖默认路径。未登记宿主标识、空取值判为参数类问题并拒绝写入。这两项配置只影响宿主分发（`--host`）的落点，不影响工作区内的目标位置。

**前置条件**：工作区已初始化；配置键属于上表；配置值通过取值域校验。

**行为**：

1. 校验配置键与取值；
2. 原子写入配置区；
3. 不触发重新登记，配置变更在下一次登记时生效。

**输出载荷**：被修改的配置键、原值、新值。

**预演与确认**：无需确认；支持预演。

### 4.4 `scan`

**用途**：发现当前环境中的 Skill 并刷新索引记录；当索引缺失或损坏时，本指令同时承担索引重建职责。

**语法**：`skill-manager scan [--root <路径>...] [--dry-run]`

**前置条件**：工作区已初始化；待扫描的根目录可达。索引文件缺失或损坏不影响本指令执行，本指令不要求索引可被读取。

**行为**：

1. 遍历根目录下的一级子目录，识别包含元数据的 Skill 目录；
2. 读取元文件与元数据块的字段；
3. 对已在索引中的 Skill 更新其投影与派生区字段；
4. 对元数据不合格的 Skill，**照常写入索引**，并以运行期结论为校验不通过承载其问题码；不得静默丢弃，也不得因单条不合格而中断整次扫描；
5. 对索引中存在但磁盘上已消失的记录，同样以校验不通过写入并给出对应问题码；
6. 对无法判定来源的 Skill 登记为来源未知，不中断执行；
7. **重新计算每个 Skill 的运行期结论并写入索引的对应区块**，该区块只由本指令写入。同一 Skill 重复扫描时更新既有记录，不新增重复条目；问题修复后结论自动转为校验通过；
8. 原子写入索引。

**输出载荷**：新增数量、更新数量、失效数量、来源未知数量的摘要，以及逐条明细。

**索引重建场景**：当索引文件缺失、损坏或格式版本不受支持且无法迁移时，本指令按下列规则承担索引重建职责：

1. 若索引文件存在，先将其副本保留到工作区的备份目录，不得直接删除；
2. 按上述行为重新生成索引的记录区；
3. 索引顶层的配置区无法由元文件推导，因此**不得从索引自身的残留内容推断配置**；配置区必须从备份恢复，或由用户重新声明；
4. 备份与用户声明均不可用时，必须在结果中明确提示配置区待重新声明，不得以默认值静默覆盖；
5. 重建属写操作，须遵守工作区写锁与原子写入要求。

重建场景的行为约束与索引格式规范第 6 章一致，二者的执行细节以索引格式规范为准，本规范只定义触发指令与输出要求。

**退出码语义**：本指令只要完成扫描即视为执行成功；但当扫描过程发现错误级问题时，**按第 5.2 节的派生规则返回对应的派生档位**（例如依赖环属 `DEP` 类 → `6`、字段类 → `1`），含义是**「扫描完成，但环境中存在不合格项」**，而不是「指令执行失败」。合格记录仍会被正常写入索引，调用方应依据结果封装中的问题列表判断具体问题，不得仅凭退出码断定扫描未执行。**第 5.2 节的派生规则是退出码的唯一权威**，本小节不另设「固定返回 1」的口径。

**预演与确认**：无需确认；支持预演。

### 4.5 `list`

**用途**：列出全部已管理 Skill。

**语法**：`skill-manager list [--state <enabled|disabled>] [--source <类型>] [--target <目标标识>]`

**前置条件**：无。索引不存在时返回引导性结果而非错误。

**行为**：

1. 读取索引记录区，不读取各 Skill 的元文件；
2. 按过滤条件筛选；
3. 按排序条件排序，默认按标识升序。

**输出载荷**：记录列表，每条含标识、名称、版本、状态、来源类型摘要、落位目标摘要与最近更新时间；以及过滤前的总数与过滤后的数量。

**预演与确认**：只读指令，不需要确认，不支持预演。

### 4.6 `inspect`

**用途**：查看单个 Skill 的完整元信息与状态。

**语法**：`skill-manager inspect <Skill 标识>`

**前置条件**：该标识在索引中存在。

**行为**：

1. 读取索引记录；
2. 读取该 Skill 的元文件，补全索引未保留的完整信息；
3. 计算或读取内容指纹并给出与磁盘的比对结论。

**输出载荷**：完整元数据字段、来源信息的完整取值、依赖声明的完整取值、落位目标的完整取值含逐文件映射、内容指纹与比对结论、索引记录原样（派生区含逐文件内容摘要 `digests`，供宿主在内容漂移时定位到具体文件；该字段属内核内部派生数据，不进导出物）、**最近扫描时间**（取索引运行期结论中的最近扫描时间字段，该字段只由 `scan` 维护；尚未扫描过的记录没有该取值）。措辞刻意避开「最近校验时间」——校验动作是只读的，不产生也不刷新任何时间戳。

**预演与确认**：只读指令，不需要确认，不支持预演。

### 4.7 `install`

**用途**：从受支持来源安装 Skill，并登记到索引。

**语法**：`skill-manager install <来源> [--target <目标标识>] [--host <宿主>] [--scope <global|project>] [--mode <copy|link>] [--library-only] [--dry-run] [--yes]`

**受支持的来源**：本地目录、**本地 Git 仓库路径**、**本地归档文件**（zip、tar、tar.gz）。

**来源的两种形式**：本地形式由元文件的 `source.location` 指向本机的仓库目录或归档文件；远端形式由 `source.url` 与 `source.ref` 指向可远程访问的地址。两种形式都受支持。

**远端形式的约束**：

| 项目 | 要求 |
|---|---|
| 协议白名单 | 只允许 `https` 与 `git`；指向本机回环地址（`127.0.0.1`、`localhost`、`::1`）的 `http` 也允许，便于自建镜像与本地测试。其他协议判为来源类问题 `E-SRC-009` |
| 认证 | 一期只支持公开来源，不做凭据管理。私有仓库会立即失败（克隆时禁用交互提示，不挂起等待输入），归 `E-SRC-010` 并引导先在本机克隆再用本地仓库路径安装 |
| 超时 | 克隆与下载都有超时上限，超时归 `E-SRC-006` |
| 体积上限 | 下载有体积上限（响应声明与实际接收两处都校验），超限归 `E-SRC-008` |
| 隔离 | 克隆与下载都在临时目录内完成，失败路径不残留；归档沿用本地的解压防护与单层下钻规则 |

默认超时为 60 秒、体积上限为 128 MB，可用环境变量 `SKILL_MANAGER_SOURCE_TIMEOUT_MS` 与 `SKILL_MANAGER_SOURCE_MAX_BYTES` 调整。

**从地址推断类型**：安装时要靠地址判断远端来源是仓库还是归档——路径以 `.zip`、`.tar`、`.tar.gz`、`.tgz` 结尾的按归档处理，其余按仓库处理。刷新时类型以元文件的 `source.type` 为准。

**来源获取规则**：

| 来源 | 获取方式 |
|---|---|
| 本地目录 | 目录本身就是内容根 |
| 本地仓库 | 用系统 `git archive` 读出该引用下的**已提交内容**（不含版本控制目录与未提交改动）；未给出引用时按默认分支 |
| 归档文件 | 解压到临时目录后作为内容根；内容根需直接包含元文件，若根下存在**唯一**子目录且该子目录内直接含元文件，则自动下钻一层（见下） |

**归档内容的自动下钻**：真实打包习惯常常在外层套一层目录，因此当解压后的根目录不含元文件时，若根下**恰好存在一个子目录**且该子目录内直接含元文件，则以下钻后的目录为内容根。多个候选子目录、或下钻后仍不含元文件，都按获取失败上报，并在说明中写明「无法确定唯一内容目录」。只下钻一层，不做递归查找。

**来源安全约束**：归档条目逐条校验，拒绝绝对路径、上级目录跳转与链接条目（`E-SRC-004`）；解压时逐级确认父目录为真实目录，堵住借符号链接写出目标目录的路径；来源标识只允许分支名、标签或提交标识的字符集且不得以短横线开头；`git` 一律以可执行文件加参数数组调用，不经 shell。环境缺少 `git` 时返回 `E-SRC-005` 并引导安装。

**前置条件**：工作区已初始化；来源可解析；目标位置可写。

**行为**：

1. 解析来源，读取待安装 Skill 的元数据并执行元数据校验；
2. 生成落位计划，逐文件确定来源路径与目标路径；
3. 执行冲突检测，检测命名冲突、落位映射冲突与目标占用冲突；
4. 计算内容指纹；
5. 写入中心库原件；
6. 按落位计划分发到目标位置；
7. 登记记录并写入派生区字段，状态置为已启用；
8. 任一步骤失败时回滚到安装前状态。

**选项语义**：

| 选项 | 语义 |
|---|---|
| `--target` | 指定落位目标；省略时使用配置区默认目标 |
| `--host` | 除工作区内目标外，另把该 Skill 分发到指定宿主的真实根（宿主适配层）；取值来自宿主注册表；与 `--target` 正交 |
| `--scope` | 指定目标的作用域 |
| `--mode` | 指定副本或链接；一期默认副本 |
| `--library-only` | 只写入中心库与登记记录，不分发到目标位置，状态置为已禁用 |
| `--dry-run` | 返回第 2 至第 4 步的结果与将发生的变更，不写入任何文件 |
| `--yes` | 跳过轻确认 |

**落位路径的解析基准**：本指令涉及的落位路径一律是**工作区根目录之下的相对路径**，按第 2.2 节的优先级链解析出工作区根目录后再拼接，**不相对调用方的当前工作目录**。因此同一份声明无论在哪个位置调用，解析结果都一致，落位位置只由工作区决定。

**目标落位根约定**：受控副本的位置由约定推导——落位根为工作区根目录下的 `.<目标标识>/skills`，该目标下的副本目录为 `<落位根>/<Skill 标识>`。元文件声明的落位路径必须与该约定一致，不一致按字段取值问题拒绝登记。约定化的理由与副本定位规则见元数据规范 3.5 节；本指令与启用、禁用、刷新、卸载都按该约定定位副本，**不依赖中心库原件是否存在**。

**选项语义的生效方式**：

| 选项 | 生效方式 |
|---|---|
| `--target` | 只向指定目标分发，其余声明目标本次不分发；取值必须是该 Skill 声明的某个目标标识，不匹配时判为参数类问题 |
| `--scope` | 只向指定作用域的目标分发；取值仅允许 `global` 或 `project` |
| `--mode` | 一期只支持 `copy`，给出其他取值判为参数类问题；链接方式属后续迭代 |

**输出载荷**：将新增或已存在的记录、**逐文件落位计划**（每个目标下的目标路径、文件数量与逐文件路径列表）、内容指纹、执行的阶段摘要。逐文件落位计划在预演与实装两种情形下呈现同一份列表。

**退出码**：存在依赖未满足问题时返回 `6`；存在冲突时返回 `1`。

**预演与确认**：轻确认；支持预演。

**重复安装**：同一来源重复安装必须被识别，返回「已安装」结果并引导至更新指令，不产生重复记录。

### 4.8 `uninstall`

**用途**：移除一个已管理的 Skill，并精确回收其带来的文件。

**语法**：`skill-manager uninstall <Skill 标识> [--keep-library] [--hard] [--dry-run] [--yes]`

**前置条件**：该标识在索引中存在。

**行为**：

1. 依据该 Skill 的落位映射，逐文件确定将被移除与将被保留的路径；
2. 生成备份并写入工作区的备份目录；
3. 移除各目标位置的文件；
4. 按选项决定是否移除中心库原件；
5. 清理索引中该 Skill 的记录，不得留下悬空记录；
6. 失败时从备份恢复。

**选项语义**：

| 选项 | 语义 |
|---|---|
| `--keep-library` | 保留中心库原件，仅移除目标位置的内容；省略时同样默认保留 |
| `--hard` | 连同中心库原件一并删除；用于清理无法修复的坏项。与 `--keep-library` 互斥，二者同时传入时判为参数类问题并拒绝执行，不自行择一 |
| `--dry-run` | 只返回将被删除与将被保留的路径，不执行删除 |
| `--yes` | 跳过强制二次确认 |

**输出载荷**：受影响的目标位置与**逐文件路径列表**、文件数量、备份位置、是否保留中心库原件。位置一律以相对工作区的可移植路径表达。副本按目标落位根约定定位，因此即使中心库原件已缺失，卸载仍能完整回收副本。

**预演与确认**：强制二次确认；支持预演。确认内容必须包含具体路径与文件数量，不得使用通用文案。带 `--hard` 时确认级别高于本指令的常规级别：必须在确认内容中单独指明中心库原件将被永久删除，且该确认不得被 `--keep-library` 的默认语义合并。

**与其他指令的关系**：卸载后若中心库原件被保留，该内容不再属于已管理集合。中心库不属于登记指令的扫描根目录，因此不会在下次登记时被重新登记。

### 4.8.1 备份载体清单（backup_meta.yaml）

**用途**：卸载前的自动备份会在备份目录内写出一份清单，记录该次备份的可追溯信息。清单是持久化产物，也是日后恢复能力的输入，因此其结构按契约固定。

**位置**：`<工作区>/backups/<Skill 标识>/<时间戳目录>/backup_meta.yaml`。时间戳目录名使用安全转写（冒号替换为短横线），清单内的字段值保持契约时间格式。

**时间戳的唯一性**：`timestamp` 是备份的对外标识，`restore --timestamp` 按它寻址，因此同一 Skill 下必须唯一。同一秒内产出多份备份时，从第二份起把清单里的时间格式**按毫秒精度扩展**（形如 `2026-10-15T12:00:00.001Z`）直到取值唯一，目录名同步按同一取值转写；读取侧按唯一取值匹配，不再出现「同一取值对应多份载体」。毫秒形式只出现在本清单，其余时间字段仍为秒级精度（元数据规范 2.2）。

**字段**：

| 字段 | 类型 | 必填/可选 | 说明 | 校验规则 |
|---|---|---|---|---|
| `type` | 字符串枚举 | 必填 | 备份载体的类型 | 当前仅允许 `full`（完整文件载体）；其余取值属二期，遇到不支持的取值时恢复动作拒绝执行（`E-BAK-005`） |
| `timestamp` | 字符串 | 必填 | 该次备份的时间，同时是该份备份的对外标识 | 满足元数据规范 2.2 的时间格式；同一标识下唯一（同秒多份时按毫秒精度扩展）；与目录名的转写形式一一对应 |
| `skill_id` | 字符串 | 必填 | 被备份 Skill 的标识 | 满足元数据规范 2.1 的命名规范 |
| `source` | 字符串 | 必填 | 被备份内容的相对路径，通常为中心库原件 | 相对工作区根目录并使用正斜杠；禁止绝对路径 |
| `file_count` | 整数 | 必填 | 副本内的文件数 | 不小于零；含元文件与附属文件 |
| `backup_digest` | 字符串 | 必填 | 载体自身的完整性摘要 | `sha256:` 前缀加 64 位小写十六进制；覆盖全部文件含元文件 |
| `content_checksum` | 字符串 | 必填 | 被备份内容按契约算法计算的内容指纹 | 同上格式；内容指纹计算失败时为空字符串 |

**未知字段**：只给警告，不拒绝读取；本工具生成的清单不含未知字段。

**机器可读形态**：`schemas/backup.schema.json` 的 `$defs.backupManifest`。

### 4.9 `enable`

**用途**：使一个已登记的 Skill 在目标位置生效。

**语法**：`skill-manager enable <Skill 标识> [--target <目标标识>] [--host <宿主>] [--scope <global 或 project>] [--dry-run] [--yes]`

**宿主入口的语义**：给出 `--host <宿主>` 时，本指令只作用于该宿主真实根内该 Skill 的副本——把副本内带禁用后缀的技能元数据文件改回原名，使宿主重新识别；**不修改索引状态**（索引状态描述工作区内目标），也不新建副本（新建副本是安装的职责）。该操作属工作区外写入，沿用确认机制。

**前置条件**：该标识在索引中存在；该 Skill 的依赖已满足。

**行为**：

1. 将索引中该记录的启用状态置为已启用，**索引状态是启用状态的唯一事实源**；
2. 按该目标的落位方式把缺失的文件补齐到目标位置；
3. **把目标位置副本内带禁用后缀的技能元数据文件改回原名**，使宿主按既有发现规则重新将其识别为 Skill；
4. 幂等：对已启用的 Skill 重复执行不产生额外变更，返回「已启用」结果。

**不可用条件**：

1. 未登记的标识：返回输入类错误，并给出登记指令建议；
2. 该 Skill 的运行期结论为校验不通过：返回校验类错误 `E-VALIDATION-001`，给出其问题码与修复建议，并提示修复后重新扫描。**该拒绝不得表述为「该 Skill 已被禁用」**，两者语义不同；
3. 该 Skill 的依赖未满足：返回依赖类错误，并给出可执行的补齐建议。

**允许的操作**：运行期结论为校验不通过的记录仍可被查看与卸载，以便用户处理问题；本指令只拒绝启用。

**输出载荷**：标识、目标位置、执行前后的状态、文件变更明细。

**预演与确认**：无需确认；支持预演。

### 4.10 `disable`

**用途**：使一个已登记的 Skill 在目标位置不再生效，同时保留其全部文件与元信息。

**语法**：`skill-manager disable <Skill 标识> [--target <目标标识>] [--host <宿主>] [--scope <global 或 project>] [--dry-run] [--yes]`

**宿主入口的语义**：给出 `--host <宿主>` 时，本指令只把该宿主真实根内该 Skill 副本的技能元数据文件改名为带禁用后缀的名称，目录与其余文件一律不动；**不修改索引状态**，也不删除任何内容。该操作属工作区外写入，沿用确认机制。

**前置条件**：该标识在索引中存在。

**行为**：

1. 将索引中该记录的启用状态置为已禁用；
2. **把目标位置副本内的技能元数据文件重命名为带禁用后缀的名称**，使宿主按既有发现规则不再将其识别为 Skill。该操作只作用于副本，中心库原件与用户源文件一律不改动；
3. 在索引中记录该状态由管理器设置，以便与用户手动删除区分；
4. 完全可逆：执行启用后状态与文件恢复到禁用前的一致状态。

**禁止行为**：不得删除任何 Skill 内容文件，也不得触发内容分发。禁用只切换该 Skill 在目标位置的可见性。

**受控副本约束**：目标位置的落位内容是内核维护的受控副本。启用与禁用只作用于该副本，且**不得移动、重命名或删除任何目录**，不得改变副本内文件之间的相对路径关系。一期统一采用副本内元数据文件改名的方式，该方式在一期固定，不逐目标配置。

**输出载荷**：标识、目标位置、执行前后的状态、执行的实际落位动作说明。

**预演与确认**：无需确认；支持预演。

### 4.11 `update`

**用途**：把已登记的 Skill 更新到其来源的较新版本。

**语法**：`skill-manager update <Skill 标识> [--all] [--check] [--target <目标标识>] [--host <宿主>] [--dry-run] [--yes]`

**前置条件**：该标识在索引中存在。

**一期语义**：update 为**按磁盘现状刷新**该记录的投影字段与派生区字段，不向来源拉取新版本。因此一期只支持本地来源：来源类型为 Git 仓库或归档文件的记录返回来源类错误 `E-SRC-001`（一期无远端能力，远端拉取属二期）。刷新会重新读取中心库原件的元文件、重算内容指纹、更新最近变更时间，首次登记时间不变；元文件与用户源文件一律不改写。

**行为**：

1. **按来源声明决定是否重新获取内容**：本地目录与来源未知不重新获取；本地仓库与归档按 `source.location` 重新获取并替换中心库原件；远端形式依赖远端拉取能力，本批次返回来源类错误；
2. 读取中心库原件的元文件，校验其合规性；元文件不可读或不合格时拒绝刷新，不写索引；
3. **来源获取失败时直接失败**（`E-SRC-003`、`E-SRC-004`、`E-SRC-005`），不刷新记录，也不改动副本；
4. 比对当前内容与记录的内容指纹，检测本地漂移：发现漂移时报告，并按磁盘现状刷新（本指令的语义就是让记录追上磁盘）；
5. 按元文件重新投影索引记录的声明区字段，并按导入时点刷新派生区字段；
6. **重分发受控副本**：按落位计划把新内容写入已存在的全部副本（`--target` 时只写指定目标），并保持各副本原有的可见性；不新建副本——分发是安装与启用的职责；
7. 顺序固定为「先重新获取与替换原件 → 再重分发副本 → 最后写索引」：任一步失败则本次刷新整体失败，索引保持调用前状态，**不产生「记录已刷新而副本或原件仍是旧内容」的中间态**。

**选项语义**：

| 选项 | 语义 |
|---|---|
| `--all` | 对所有可更新的 Skill 依次执行，单个失败不阻断其余项 |
| `--check` | 只检查并报告本地漂移与版本差异，不写入任何文件（一期没有远端版本可查，检查落在本地漂移上） |
| `--target` | 只重分发指定目标的副本，其余副本本次不刷新 |
| `--host` | 刷新后按落位计划把新内容重分发到指定宿主的真实根；只作用于已存在的宿主副本，不新建副本；与 `--target` 正交 |
| `--dry-run` | 返回新旧差异与将发生的变更，不写入任何文件 |
| `--yes` | 跳过轻确认 |

**输出载荷**：标识、原版本与新版本、各目标的更新结果、内容指纹的前后取值、被阻断的项与原因。

**退出码**：来源不可解析时返回 `4`；依赖未满足时返回 `6`。

**预演与确认**：轻确认；支持预演。

**显式触发约束**：更新只能由用户显式发起，不得在后台自动执行。自动更新与后台升级不属于本规范范围。

### 4.12 `validate`

**用途**：校验元数据、配置与索引是否合规。

**语法**：`skill-manager validate [<路径或标识>] [--strict] [--json]`

**前置条件**：无。索引不存在时报告环境类问题而非崩溃。

**行为**：

1. 不带参数时校验整个环境：全部 Skill 的元数据与元文件、索引文件、配置区；
2. 带参数时只校验指定对象；
3. 按元数据规范的校验规则总表逐项判定，结论分级为错误与警告；
4. **全程只读**，不得修改被校验对象，不得修复任何文件；
5. 不得写入或刷新索引中的运行期结论。索引中已有的结论与实时读取的元数据共同构成报告依据；判定结论已过期时，在报告中提示「建议重新扫描」并给出对应的索引类警告，由用户显式触发 `scan` 完成更新。

**选项语义**：

| 选项 | 语义 |
|---|---|
| `--strict` | 把警告级问题也视为失败，退出码按失败返回 |
| `--json` | 输出结构化的校验报告 |

**输出载荷**：通过数量、警告数量、错误数量，以及按分级归类的逐条明细，每条含问题码、位置与修复建议。内容漂移的明细**逐文件**给出：每条含该文件的相对路径与新旧内容摘要（判据为索引派生区的逐文件摘要，见元数据规范 2.3 与 5.4 节）；索引内尚无该基准时只有聚合级条目，并提示重新扫描以补齐基准。

**退出码**：本指令采用专属口径，**不适用结果规范第 5.2 节的通用派生规则**：存在错误级问题时返回 `1`；仅存在警告时返回 `0`；`--strict` 下警告级问题也视为失败，返回 `1`；参数类问题（`E-INPUT-*`）返回 `2`。因检查类结论一律归入「发现问题」语义，本指令不会返回 `3`、`4`、`5`、`6`，即使报告中出现依赖类或版本类问题码也不例外。

**预演与确认**：只读指令，不需要确认，不支持预演。

### 4.13 `deps`

**用途**：检查一个 Skill 声明的依赖是否满足，并报告影响面。

**语法**：`skill-manager deps <Skill 标识> [--tree] [--json]`

**前置条件**：该标识在索引中存在。

**行为**：

1. 存在性检查：被依赖的 Skill 是否已登记且结论为校验通过；同时**实时探测**该 Skill 声明的外部运行时是否可用（按平台解析可执行文件：POSIX 用 `command -v`，Windows 用 `where`）；
2. 版本检查：被依赖 Skill 的版本是否满足约束；外部运行时则执行其 `--version` 并把输出解析为语义化版本，再按声明的范围表达式判定是否满足（`>=`、`^`、`~`、`1.2.x` 等写法均按语义化版本范围解释）；
3. 完整性检查：依赖关系是否成环，成环必须被检出并报告；
4. 影响面分析：报告哪些其他 Skill 会因该 Skill 被卸载或被禁用而受影响。

**运行时的探测边界**：

- 探测**不写入任何文件**：运行时的可用性与版本属环境相关数据，**不入索引、不入运行期结论**（元数据规范 3.3 与 5.3）——索引保持环境无关，同一份索引在不同机器上含义一致；
- 探测结果**不改变 Skill 的校验结论**：运行时缺失或版本不满足只在本指令的报告中呈现，`scan` 与 `validate` 的结论仍只取决于 Skill 自身的内容与声明；
- 约束不可解析、`--version` 输出无法解析出语义化版本、探测命令无法执行或超时，各自归入明确的问题码，**不静默忽略**；
- 探测命令以参数数组调用、不经 shell，运行时的名称只作为参数传递，不作为命令文本拼接。

**约束**：只检查、只报告，**不自动安装任何依赖**，也不安装任何运行时。输出必须包含可直接执行的修复建议。

**输出载荷**：依赖条目列表，每条含对象名、版本约束、当前状态与检查结论；**运行时条目列表**，每条含运行时名称、期望的约束原文、探测到的版本、命中命令的位置与结论；以及受影响对象列表。

**退出码**：存在未满足的依赖时返回 `6`；运行时缺失、版本不满足、约束无效或版本无法解析同样归入该档（结果规范的运行时类问题码属于依赖档）。

**预演与确认**：只读指令，不需要确认，不支持预演。

### 4.14 `export`

**用途**：把当前的元信息与索引状态导出为一份可迁移的备份。

**语法**：`skill-manager export <文件路径> [--no-config] [--no-secrets]`

**前置条件**：工作区已初始化；目标文件路径可写。

**行为**：

1. 收集索引的完整内容、各 Skill 的元数据与来源信息、状态与落位映射、内容指纹；
2. 剥离敏感信息并显式记录被剥离项的清单；
3. 写入备份自身格式版本标识与导出时间；
4. 备份不以绝对路径表达位置，以保证可在不同机器与不同用户目录下导入。

记录的字段集固定为契约列明的字段；派生区中的**逐文件内容摘要 `digests`** 属内核内部派生数据（用于把内容漂移定位到具体文件），既不写入导出物，也不计入被剥离项清单——它不是敏感信息，也不是用户自研字段，列入清单只会掩盖真正的剥离项。聚合指纹 `checksum` 仍在导出物中，导入时按磁盘现状重算两级取值。

**选项语义**：

| 选项 | 语义 |
|---|---|
| `--no-config` | 不包含配置区；默认包含 |
| `--no-secrets` | 显式剥离敏感信息；默认执行剥离 |

**输出载荷**：备份文件路径、包含的条目数量、被剥离项清单、备份格式版本。

**预演与确认**：无需确认；支持预演，预演时不生成文件。

### 4.15 `import`

**用途**：从备份文件恢复元信息与索引状态。

**语法**：`skill-manager import <文件路径> [--on-conflict <keep|use-backup|keep-both>] [--dry-run] [--yes]`

**前置条件**：备份文件存在且可解析。

**行为**：

1. **先校验后导入**：校验备份的格式版本、结构与内容指纹；校验失败必须整体拒绝，不得部分导入；
2. 预演：展示将新增、将覆盖与将冲突的条目；
3. 冲突时按显式指定的策略处置，不得静默覆盖；
4. 若磁盘实际内容与备份记录不一致，先报告「本地已修改」，由用户决定如何处置；
5. 导入失败时环境保持导入前状态。

**选项语义**：

| 选项 | 语义 |
|---|---|
| `--on-conflict` | 冲突策略：保留旧值、采用备份值、两者并存。省略时必须交互确认，不得自行选择 |
| `--dry-run` | 只展示预演结果，不写入任何文件 |
| `--yes` | 跳过轻确认；与冲突策略同时使用时，策略必须已显式给出 |

**输出载荷**：新增、覆盖、冲突与跳过的条目明细，以及对往返一致性的结论。

**退出码**：备份格式或指纹校验失败时返回 `3`；来源类读取失败时返回 `4`。

**预演与确认**：轻确认；支持预演。

### 4.16 `restore`

**用途**：把某个 Skill 的备份载体恢复回工作区——内容写回中心库、重分发到各目标位置、刷新或重建索引记录。

**与 `import` 的分工**：`restore` 用**备份载体**恢复**单个 Skill 的内容与记录**；`import` 用**导出清单**批量恢复**索引记录**。前者动文件，后者只动记录。

**语法**：`skill-manager restore <Skill 标识> [--timestamp <时间戳>] [--dry-run] [--yes]`；列出可用备份用 `skill-manager restore --list [<Skill 标识>]`

**前置条件**：工作区已初始化；该标识存在可用的备份载体。

**列出可用备份（`--list`）**：这条取值选项为备份管理界面提供数据来源——界面不得直接读取工作区文件（含备份目录），因此备份列表由本指令产出。它只读取各载体的清单（标识、时间戳、载体类型、文件数、载体位置），**不校验载体内容**，也不要求索引可读：工作区尚未初始化或备份目录不存在时返回空列表，属正常结果而非错误。给出标识时只列该标识的备份（标识不符合命名规范按参数类问题拒绝），省略时列出工作区内全部标识的备份，按标识与时间戳升序。

**行为**：

1. 按标识枚举备份载体，按清单里的时间戳升序；省略 `--timestamp` 时取最新的一份。枚举按**清单声明的契约格式时间戳**排序，目录名的安全转写不参与比较；
2. 校验载体自身的完整性：载体类型须受支持、内容目录须存在、文件数与载体摘要须与清单一致；不通过即拒绝，不写任何内容；
3. 读取载体内容里的元文件并校验；不可用或不合格时拒绝，不写任何内容；
4. 把载体内容写回中心库原件位置。该位置被同名**文件**占用时按目标占用冲突拒绝；被同名目录占用时按覆盖处理（见确认要求）；
5. 按落位计划重分发到各目标位置：已存在的副本刷新内容并**保持原有可见性**，不存在的按元文件声明创建；
6. 刷新或重建索引记录：标识已登记时刷新投影与派生区，未登记时重建记录。**运行期结论不在本指令判定**——已登记的记录保持原结论不动，重建的记录取保守值，两种情况都提示执行扫描；
7. 备份载体是**只读消费**：恢复不改动任何备份，备份保留策略不变（一期不自动清理）。

**选项语义**：

| 选项 | 语义 |
|---|---|
| `--timestamp` | 指定要恢复的备份时间戳；必须是该标识某个备份清单里记录的取值，不存在时判为参数类问题并列出可用取值 |
| `--dry-run` | 返回将写回的文件清单与目标位置，不写入任何文件 |
| `--yes` | 跳过常规确认 |
| `--list` | 只列出可用备份载体，不写入任何内容；可与位置参数并用（给出标识表示只列该标识的备份）。与 `--dry-run`、`--yes` 同时给出时以本选项为准 |

**输出载荷**：恢复的逐文件路径列表与文件数量、备份位置与时间戳与载体类型、中心库位置、各目标的重分发结果（是否新建、可见性、文件数与逐文件路径）、记录是刷新还是重建，以及「请执行扫描」的提示。

**输出载荷（`--list`）**：`backups` 数组，每项含 Skill 标识、时间戳、载体类型、文件数与载体位置（相对工作区根目录）；`total` 为条目总数；`filtered_by` 为本次过滤用的标识或 `null`；`notes` 说明「列表只读清单、恢复时才校验载体」以及无备份时的引导。

**退出码**：没有可恢复的备份返回 `5`；载体损坏或类型不受支持返回 `5`；目标被占用返回 `1`；时间戳不存在返回 `2`。`--list` 恒为 `0`：列表为空是正常结果，不是失败。

**预演与确认**：常规确认；支持预演。目标位置已有原件时，确认内容必须写明将覆盖现有原件。`--list` 是只读选项，不参与确认流程。

## 6. 契约稳定性与扩展

### 6.1 稳定性规则

1. 指令名一旦发布不得改名，也不得改变语义；
2. 既有选项不得删除，也不得改变语义；
3. 新增选项必须是可选的，且不得改变省略时的既有行为；
4. 指令的位置参数顺序不得调整；
5. 退出码与问题码的定义以结果封装与退出码规范为准，本规范不得另行定义。

### 6.2 新增指令

新增指令必须满足下列全部条件：

1. 先修订需求文档的功能清单，再修订本规范，最后才可实现；
2. 新指令不得与既有指令的语义重叠；
3. 新指令必须有明确的写操作属性与确认级别；
4. 新指令必须复用既有的结果封装结构。

### 6.3 界面宿主的约束

1. 界面上的每一个动作必须对应本规范中的一条指令；
2. 界面不得把多条指令合并为一次调用，也不得对指令名做映射或改写；
3. 涉及文件路径的参数必须来自宿主提供的原生文件选择器，界面不得自行构造路径；
4. 按钮的可用性必须依据内核返回的判定结果，界面不得自行推断。
