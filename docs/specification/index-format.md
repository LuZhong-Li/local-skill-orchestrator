## 1. 文档概述

### 1.1 目的

本规范定义全局索引文件 `skill_index.yaml` 的**文件级契约**：它的位置、序列化要求、写入时机、与元文件的投影关系、一致性判定与重建流程。

### 1.2 与元数据规范的分工

两份规范共同定义同一个文件，分工如下，二者不重叠：

| 规范 | 负责 |
|---|---|
| [`skill-meta-spec.md`](skill-meta-spec.md) | 索引中每个字段的**名称、类型、必填性、归属分区与取值校验规则** |
| 本文档 | 索引的**文件级契约**：位置、结构不变量、写入时机、投影规则、一致性判定、重建与迁移 |

字段定义请查阅元数据规范第 4 章，本文档不重复。

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| **索引** | 工作区根目录下的 `skill_index.yaml`，记录全部已管理 Skill 的引用信息 |
| **元文件** | 每个 Skill 独立目录下的 `skill_meta.yaml`，是该 Skill 配置的权威来源 |
| **投影** | 索引中由元文件对应字段派生而来的取值 |
| **投影一致性** | 索引记录与元文件对应字段取值相同的状态 |
| **配置区** | 索引顶层承载管理器运行配置的区域，不可由元文件推导 |
| **记录区** | 索引顶层承载全部 Skill 引用记录的列表 |
| **悬空记录** | 索引中存在、但磁盘上已找不到对应目录或元文件的记录 |
| **未登记 Skill** | 磁盘上存在合法元文件、但索引中没有对应记录的情况 |

## 2. 文件级契约

### 2.1 位置与数量

| 项目 | 要求 |
|---|---|
| 位置 | 工作区根目录，与 `./skills/` 目录同级 |
| 文件名 | `skill_index.yaml`，不得改名 |
| 数量 | 一个工作区有且仅有一份索引 |
| 与元文件的关系 | 一个工作区可以有任意多个元文件，每个 Skill 目录各一份 |

**工作区根目录的确定**：按优先级链取值，命令行选项 `--workspace` 高于环境变量 `SKILL_MANAGER_HOME` 高于默认目录（用户主目录下的 `.skill-manager`）。该链的定义与指令契约规范第 2.2 节一致，本规范不另行定义。

### 2.2 序列化要求

索引的文件编码、换行、缩进、文档流、锚点与引号规则，全部沿用元数据规范第 2.4 节的 YAML 基础约束，本文档不再重复。

在此基础上，索引额外要求：

| 要求 | 说明 |
|---|---|
| 顶层为映射 | 顶层不得为序列或标量 |
| 记录列表为序列 | 记录区必须是序列，每项为一个映射 |
| 记录顺序 | 记录顺序不构成契约，读取方不得依赖顺序 |
| 时间与指纹加引号 | 按元数据规范的引号规则书写，避免被解析为数值或其他类型 |
| 未识别字段保留 | 读取到未识别字段时必须原样保留，不得在改写时丢弃 |

### 2.3 文件级不变量

下列条件在索引的任何合法状态下都必须成立：

1. 顶层字段齐全，类型正确；
2. 记录区内每个记录的标识在索引内唯一；
3. 每条记录必须携带完整的派生区字段；
4. 记录区中不得存在两个指向同一目标标识与作用域的落位目标摘要；
5. 索引文件的全部取值必须可被当前的格式版本所解释。

## 3. 生命周期与写入时机

### 3.1 创建

工作区初始化时创建索引，此时记录区为空，配置区写入首次初始化所确定的配置。

### 3.2 写入时机

| 触发动作 | 对索引的影响 | 是否可由用户直接编辑 |
|---|---|---|
| 初始化 | 创建索引与配置区 | 否 |
| 登记与刷新 | 新增、更新或标记记录的派生区字段（含逐文件内容摘要 `digests`），**并重新计算运行期结论** | 否 |
| 安装 | 新增记录，并写入该 Skill 的派生区字段（含逐文件内容摘要 `digests`） | 否 |
| 卸载 | 移除该 Skill 的记录 | 否 |
| 启用 | 更新该记录的启用状态 | 状态允许编辑，其余字段不允许 |
| 禁用 | 更新该记录的启用状态 | 同上 |
| 更新 | 刷新该记录的投影字段与派生区字段（含逐文件内容摘要 `digests`） | 否 |
| 校验 | 不改写索引，仅报告不一致 | 不适用 |
| 导入 | 按冲突策略新增或覆盖记录 | 否 |
| 配置变更 | 更新配置区 | 配置区允许编辑 |

写入权限说明：**运行期结论只由登记与刷新动作写入或刷新**，其余动作对该区块一律只读。安装、卸载、更新与导入会改变记录本身，但不直接改写运行期结论；结论的变化统一下一次登记与刷新时体现。校验动作对该区块保持只读，详见 5.2 节。

运行期结论中的**最近扫描时间**字段同样只由登记与刷新动作写入：它记录该结论被计算出来的时刻，因此安装新登记的记录在首次扫描之前没有该取值，缺失按「尚未扫描」处理。字段定义见元数据规范 4.4 节。

### 3.3 写入方式

1. 索引的任何写入必须采用原子写入，中途中断不得留下半成品文件；
2. 写入前必须获取工作区写锁，锁文件位于工作区的锁目录；
3. 读取索引不需要获取写锁；
4. 写入失败时必须回滚到写入前的状态，并返回文件系统类别的错误码。

### 3.4 写入主体

| 主体 | 可写范围 |
|---|---|
| 管理器内核 | 索引的全部字段 |
| 用户 | 配置区，以及各记录的启用状态字段 |
| 其他工具 | 不得写入 |

用户直接修改配置区与启用状态之外的字段，属于超出契约的编辑行为，校验时按投影不一致或派生区篡改报告。

## 4. 投影规则

### 4.1 投影来源

索引记录中的每个字段都有一段确定的来源，分为三类：

| 来源类别 | 说明 | 可否由元文件重建 |
|---|---|---|
| 元文件投影 | 取值直接来自该 Skill 元文件的对应字段 | 可以 |
| 内核计算 | 由内核在安装、更新、校验时计算得出，例如内容指纹与时间字段 | 部分可以，内容指纹可重算，时间字段不可还原历史值 |
| 引用摘要 | 由元文件对应结构压缩而来的摘要形式，例如来源类型摘要与落位目标摘要 | 可以 |
| 运行期结论 | 由扫描动作对当前环境状态作出的判定，例如校验结论与其问题明细 | 不可以，且不适用：该类别不来自元文件 |

索引由上述四类来源构成，不存在第五类。需要特别说明的是：**索引不承载元文件之外的持久配置信息**——声明区与派生区都是元文件的投影或其派生值，而运行期结论虽然在形式上存在于索引之内，但它是内核每次扫描重新计算的判定结果，不是配置，也不是可编辑数据，因此不违背本条约束。

### 4.2 投影一致性判定

| 情形 | 判定 |
|---|---|
| 索引取值与元文件一致 | 投影一致 |
| 索引取值与元文件不一致 | 投影不一致，报告为警告，并以元文件为准。比对集合以元数据规范 5.7 节为准：该节排除的字段（`status` 与 `targets.enabled`）属于运行期事实而非元文件投影，不在本条判定范围内 |
| 索引缺少记录而元文件存在 | 判定为未登记 Skill，报告为警告 |
| 索引存在记录而元文件缺失 | 判定为悬空记录，按记录失效处理，报告为错误 |
| 索引存在记录、元文件也存在，但内容不合格 | 记录**保留在索引内**，其运行期结论为校验不通过并携带问题码；该情形不是悬空记录，也不得据此删除记录 |

### 4.3 投影的权威性

1. 凡属投影的字段，权威来源一律为元文件；
2. 索引中的取值为消费副本，用于检索与列示，不作为配置的编辑入口；
3. 用户需要修改投影类字段时，应先修改 Skill 自身的元数据或元文件，再由内核重新生成投影，不得直接编辑索引。

## 5. 一致性校验

### 5.1 校验维度

| 维度 | 检查内容 | 出现问题码 |
|---|---|---|
| 结构 | 顶层字段齐全、类型正确、记录区为序列 | 字段类错误 |
| 唯一性 | 记录标识在索引内唯一 | 标识类错误 |
| 引用可达性 | 记录的路径指向的目录与元文件确实存在 | 路径类错误 |
| 投影一致性 | 索引取值与元文件一致 | 索引投影类警告 |
| 内容一致性 | 记录的内容指纹与磁盘内容一致 | 内容漂移类警告 |
| 双向覆盖 | 无悬空记录，也无未登记 Skill | 记录失效类错误与索引投影类警告 |
| 版本 | 格式版本可被当前工具解释 | 版本类错误 |
| 结论时效 | 运行期结论是否由最近一次扫描产生 | 索引类警告 |

### 5.2 校验的只读性

校验必须只读：不得改写索引、不得重建投影、不得修复任何文件。校验只负责报告，处置由用户显式触发的指令完成。

对运行期结论的专门约束：**校验动作不得写入或刷新运行期结论**。校验基于索引中已有的结论与实时的元数据读取出报告；当判定结论已过期时，校验在报告中提示「建议重新扫描」并给出对应的索引类警告，由用户显式触发登记与刷新来完成更新。

### 5.3 报告要求

1. 每条问题必须给出问题码、位置与可执行的修复建议；
2. 投影不一致必须同时给出索引取值与元文件取值；
3. 内容漂移必须逐文件指出发生变化的文件相对路径与其新旧摘要：索引派生区的 `digests` 提供了逐文件基准，因此本条不再是「可行时」的可选要求，而是**必须**——每一条变化单独成项，覆盖内容变化、新增与删除三种情形。仅当索引内缺少 `digests`（旧索引尚未回填逐文件基准）时，才退化为聚合级报告：给出记录指纹与重算指纹，并提示重新扫描以补齐基准；此时不得凭空指出文件。

## 6. 索引重建

### 6.1 重建的适用范围

索引的重建语义分两部分，二者必须分别对待：

| 区域 | 可否重建 | 说明 |
|---|---|---|
| 记录区 | 可以 | 由各 Skill 的元文件与磁盘内容完整重新生成 |
| 配置区 | 不可以 | 其内容无法由元文件推导，删除索引会一并丢失全局运行配置 |

因此删除索引属于**部分破坏性操作**：记录区可恢复，配置区必须依赖备份。

### 6.2 触发条件

下列情形需要重建索引：

1. 索引文件缺失；
2. 索引文件损坏或无法解析；
3. 索引格式版本不受当前工具支持且无法迁移；
4. 用户显式发起重建。

上述四种情形均由 `scan` 承担重建职责：前三种为被动触发，第四种为主动触发。指令的参数、行为与输出要求见指令契约规范第 4.4 节；本节只定义重建的内容与边界，二者不得出现不一致。

### 6.3 重建流程

1. 若索引文件存在，先将其副本保留到工作区的备份目录，不得直接删除；
2. 扫描配置区声明的 Skill 根目录，识别其中的 Skill 目录；
3. 读取每个 Skill 的元文件，取得声明区字段；
4. 计算或读取派生区字段，写入记录；
5. 从备份或用户输入恢复配置区；
6. 原子写入新的索引文件。

### 6.4 重建的边界

1. 重建必须依据元文件，不得依据索引自身的残留内容；
2. 元文件缺失或不合规的 Skill 不得被静默忽略，必须在结果中报告；
3. 配置区无法恢复时，必须明确提示用户重新声明，不得以默认值静默覆盖；
4. 重建过程中不得修改任何 Skill 的元文件或内容。

## 7. 版本与迁移

### 7.1 版本字段语义

索引顶层的格式版本字段表达**索引文件自身的结构版本**，与工具版本无关。二者取值不同并不意味着索引不可用。

### 7.2 版本兼容判定

| 索引版本与当前支持的关系 | 行为 |
|---|---|
| 等于当前支持版本 | 正常读取 |
| 低于当前支持版本 | 允许读取并给出提示；按迁移说明决定是否升级 |
| 高于当前支持版本 | 拒绝读取索引，提示升级工具，返回版本类错误码 |
| 字段缺失 | 判定为不合规，返回版本类错误码 |

### 7.3 迁移流程

1. 迁移前必须把现有索引复制到工作区的备份目录；
2. 迁移必须产出新的索引文件，不就地逐字段改写；
3. 无法映射的字段必须保留原值并单独记录，不得丢弃；
4. 迁移失败时索引必须保持迁移前状态；
5. 迁移完成后必须执行一次一致性校验，并报告结果。

### 7.4 变更分级

| 变更类型 | 是否递增格式版本 | 是否需迁移说明 |
|---|---|---|
| 新增可选字段 | 否 | 否 |
| 新增枚举取值 | 否 | 否 |
| 收紧取值域 | 是 | 是 |
| 删除字段或改变语义 | 是 | 是 |
| 改变必填性 | 是 | 是 |

## 8. 约束边界

1. 本规范不定义索引字段的名称、类型与取值规则，见元数据规范第 4 章；
2. 本规范不定义元文件的格式，见元数据规范第 3 章；
3. 本规范不定义各指令的参数与行为，见指令契约规范；
4. 本规范不定义问题码与退出码，见结果封装与退出码规范；
5. 本规范不定义界面呈现，也不定义工作区的完整目录布局，后者见需求文档 4.3 节；
6. 索引的字段定义与本文档的文件级契约发生冲突时，以元数据规范为准，并同步修订本文档。
